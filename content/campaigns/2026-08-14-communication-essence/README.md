# 「伝える技術の本質」ブログ制作記録

## 目的

- 誰に: 発表、告知、資料、SNS、AIへの依頼がうまく伝わらない大学生、地域事業者、支援者
- 悩み: 情報を増やすほど要点が見えず、相手の行動につながらない
- 読後の行動: 一つの制作物を「誰に・悩み・次の行動・最後の一文」で書き直す
- 媒体: AI相談ブログ。公開後はnote、YouTube、Instagram、Threadsへ再編集する
- 中心命題: 伝える人が複雑さを引き受け、相手の次の一歩を軽くする

## 引用と事実の境界

- 運営者提供: 冒頭の日本語全文、AI相談全体へ考え方を浸透させたい意図
- 公式確認: Patrick H. Winston「How to Speak」の、ジョークで始めない、投影文を読み上げない、重いスライドを避ける、象徴・標語・物語で記憶に残すという教え
- AI相談一次情報: 現在の公開導線「持ち込む → 一緒に動かす → 手順に残す」、講習・相談・受講資料・ブログ・実績サイトの構成
- 表現上の判断: 冒頭の日本語全文はWinston教授の逐語訳と断定せず、「講義の本質を圧縮した運営者メモ」として扱う
- 作らない事実: 架空の受講者、顧客の発言、成果数値、未確認のMIT発言

## タイトル案3つ

### 1. 推奨

伝える技術の本質は「相手の次の一歩を軽くすること」──AI相談で実践する100→10→1

- 角度: 本質を最初に答え、AI相談の実践へ接続する
- 対象読者: 大学生、地域事業者、支援者
- 解決する悩み: 説明しているのに相手が動かない
- 読後の行動: 「誰に・悩み・次の行動・最後の一文」で一つの資料を直す
- 検索意図: 伝える技術、本質、わかりやすい説明、AI文章

### 2.

AIで文章が増えるほど、なぜ伝わらなくなるのか？──MITの名講義から学ぶ4つの順番

- 角度: AI時代の情報過多から入る
- 対象読者: AIで文章や資料を作り始めた人
- 解決する悩み: AIの出力は多いが、要点を決められない
- 読後の行動: 共感 → 理解 → 削る → 残すの順で編集する
- 注意: 冒頭の日本語全文をMIT公式の逐語訳と誤解させない注記が必要

### 3.

説明しているのに伝わらない理由──AI相談の「持ち込む・一緒に動かす・手順に残す」で考える

- 角度: AI相談の実践例を主役にする
- 対象読者: 講習・相談を検討する地域事業者
- 解決する悩み: AIやサービスの説明が抽象的に見える
- 読後の行動: 止まっている仕事を一つ持ち込む
- 弱み: 引用の普遍性よりAI相談の紹介が前へ出やすい

## H2構成案3つ

### A. 推奨: 本質 → 実話 → 順番 → 実践

1. 伝える技術の本質は、相手が次に動ける状態をつくること
2. AI相談の「持ち込む→一緒に動かす→手順に残す」は、説明より先に体験をつくる
3. 一節を4つの順番に並べると、共感→理解→削る→残すになる
4. 今日の発表や告知は「誰に・何を・次に何をしてほしいか」で整えられる

### B: AI時代の問題 → MITの教え → AI相談 → チェックリスト

1. AIは制作量を増やしたが、受け手の時間は増やしていない
2. Winston教授の講義は、冒頭・視覚・記憶の使い方を変える
3. AI相談は説明を減らし、実際の仕事を一つ動かす
4. 公開前に「100→10→1」で見直す

### C: 大学生の発表 → 失敗 → 修正 → 事業への応用

1. 調べた20本を全部話すと、聞き手には何も残らない
2. 最初の失敗は、相手ではなく自分の都合から始めること
3. 一枚・一章・一投稿に一つの役割を与える
4. AI相談、地域告知、福祉・教育の説明にも同じ原則を使う

## 採用理由

タイトル1と構成Aを採用。ユーザーが求めた「本質」「AI相談との相性」「実際のストーリー」「大学生にも分かる順序」を、最短で同時に満たせるため。

最終タイトルレビューでも変更なし。冒頭で本質に答え、AI相談との接続と「100→10→1」の持ち帰り方まで一文で示せているため。

## 画像方針

- すべて青緑、淡い青、少量のコーラルを使った、余白の多い編集イラスト
- 画像内テキスト、ロゴ、透かし、実在人物・実在施設に見える描写は使わない
- ヒーロー: 多くの情報を一本の道と一枚の持ち帰りカードへ整理する
- H2-1: 複雑な情報から次の一歩が見える
- H2-2: 持ち込む → 一緒に動かす → 手順に残す
- H2-3: 共感 → 理解 → 削る → 残す
- H2-4: 100枚 → 10枚 → 1枚の持ち帰りカード
