# AIハブ 新方針：CEOポータル + 講習資料・データ表示（2026-05-11）

## CEO からの方針指示（2026-05-11）

> 「AIハブを CEO のポータルサイトと講習の資料やデータ表示などしたい」

## 解釈と確定事項

### 1. ポータルとしての性格
- **9事業 + 個人活動のハブ**（全事業への入口）
- 訪問者はここから各事業サイト・各種資料へ飛ぶ
- 「由井辰美 = クライミング歴30年・複数事業オーナー」という属人ブランドの集約点
- → **事業ロゴ集 + 講師プロフィール + 各事業の概要カード + 各種資料リンク** が最小構成

### 2. 「公衆資料」の中身（CEO 選択・複数）
| 種類 | 現状 | 拡張方針 |
|---|---|---|
| **講習・セミナー資料** | `content/lectures/*.md` に既存 | **最優先軸**。PDF/スライド DL + バージョン管理 + 資料一覧ページ |
| **事業レポート・白書** | 未対応 | 各事業の知見をオープン化（工務店/エステ/クライミング業界の実践レポート） |
| ~~ブログ・オピニオン~~ | ~~未対応~~ | **❌ 廃止**（2026-05-11 CEO 確認）。代わりに **SNS 一括投稿機能** を実装 |
| **SNS 投稿（新規）** | 未対応 | **AIハブ管理画面から X/Instagram/Facebook 等に一括投稿**。下書き AI 生成 + 各SNS 文字数調整 + 同時公開 |
| **講演・イベント履歴・メディア掲載実績** | 未対応 | 信用構築・仕事依頼の決定打 |

### 3. 「データ表示」の追加軸（2 通目の指示で明確化）
- 単なる文書 PDF ではなく **数値データの可視化**を含む
- 候補:
  - 講習受講者数の推移
  - 各事業の業界統計（工務店/エステ/クライミングジム数等）
  - クライミング関連データ（グレード分布・岩場利用統計等）
  - AI ハブ既存パイプラインで集めている AI/SNS トレンドの可視化
- 表現手段: **静的な表 + 軽量チャート（Chart.js / Recharts）**

### 4. 既存 AI 集約パイプラインの扱い
- **裏方で維持・ポータル機能はフロント拡張として共存**
- `run.py`（RSS 収集）+ NotebookLM 連携 + カラーミー本店記事生成 = 全部そのまま
- ポータル UI は新トップページ（`/`）として作り、既存の AI 集約結果は `/watch/` 等のサブパスへ移動

## 技術判断

### 維持
- **Vercel + Supabase 集約** ([ai-hub.md](../ai-hub.md))
- `daily.yml`（GitHub Actions JST 07:00 → run.py → commit back）
- `pages.yml`（GitHub Pages 配布・参考残置）
- Supabase `ai_watch.*` スキーマ（**改名しない**）
- カラーミー本店連携（`COLORME_ACCESS_TOKEN`、現状 1086 を本番テンプレ）

### 追加が必要
| 機能 | 方針 |
|---|---|
| **資料 PDF 配信** | Supabase Storage（`ai-hub-public` バケット既存）に PDF 直置き → 直リンクで DL |
| **チャート描画** | **Recharts**（React 標準・SSR可・依存軽量）。Chart.js より Vercel と相性良い |
| **データ管理** | 講習受講者・業界統計は **Supabase に専用テーブル**（`ai_watch.*` ではなく `portal.*` 新スキーマ） |
| **MDX サポート** | レポート長文用に Next.js + `next-mdx-remote`（ブログ廃止のため最小限） |
| **OG 画像自動生成** | `@vercel/og` で資料・データページの OG カード（SNS 拡散効果大） |
| **構造化データ** | 親 CLAUDE.md 規約に従い Article / FAQPage / Speakable を出力 |
| **SNS 一括投稿 API** | **新規実装**。下記 SNS API 統合が必要 |

### SNS 一括投稿の MVP（2026-05-11 確定）

**advisor 調査結果（[work 内 a78296...]）を踏まえ、X + Threads の最小2本に絞る**。Instagram/Facebook は後フェーズ（事業ページ経由で App Review 通過が必要・2〜4 週間）。

| SNS | API 種別 | 月額 | 月間上限 | 認証 | 画像 | 文字数 | 審査 |
|---|---|---|---|---|---|---|---|
| **X** | Free | $0 | 500投稿/月 | OAuth 2.0 + 開発者アカウント | 任意 | 280字 | 軽（即時） |
| **Threads** | Threads API | $0 | 250投稿/24h（≒7,500/月） | Meta開発者 + Threadsアカウント | 任意 | 500字 | 中 |

**MVP 機能スコープ**:
1. `/admin/sns-post` 新規ページ（Basic 認証配下）
2. テキスト入力 + 画像アップロード（任意）
3. **AI下書きボタン** … `ANTHROPIC_API_KEY` で Claude 呼び出し → X 用 280 字 / Threads 用 500 字を自動生成
4. プラットフォーム別微調整 UI（X 280 / Threads 500・末尾ハッシュタグ差分テンプレ）
5. 同時投稿ボタン → X API + Threads API を並列で叩く
6. 投稿履歴ログ（Supabase `portal.sns_posts`）

**実装規模**: advisor 見積もり **1〜2 日**（既存 `/admin` 拡張・トークン管理が30%）

**Instagram / Facebook は第2フェーズ**:
- Nデザイン or ぐっぼるの公式 Facebook ページに紐づけて Business Verification → App Review 提出
- 2〜4 週間の審査期間を覚悟
- Instagram は **画像必須**（DALL-E 3 連携が前提）

**「やめておけ」**: X Basic ($200/月) への課金は CEO 投稿頻度想定では過剰。Free 500/月で頭打ちしてから判断。

### SaaS 代替案（実装前に CEO 判断必要）

| 選択肢 | 月額 | 自作との差分 |
|---|---|---|
| **自作 X+Threads MVP** | $0 | AI 生成→そのまま投稿のワンストップ性。実装1〜2日。トークン管理の保守コスト |
| **Buffer** | $6 | 4 SNS 同時投稿可・予約投稿あり。AI 連携は手動コピペ |
| **Hootsuite Free** | $0 | 制限多い。実用的でない |
| **Make.com 無料枠** | $0 | ノーコード自動化。Anthropic→各SNS のフロー組める |

**自作の正当化条件**: 「Anthropic で文章生成 → そのまま投稿」のワンストップ性が業務上必須な場合のみ。下書き確認を挟むなら Buffer 月$6で足りる。
