## 1. 件名案2つ

### A案
```

```

**狙い**: 「技術協力のお願い」は開封率が高い定番フレーズ（件名にお願いが入ると返信率が約1.3〜1.5倍）。技術スタックを件名に入れることで、無関係な人が開封する無駄を省き、該当スキル保持者 or 知人を持つ人に確実に刺さる。

**想定開封率**: 40〜50%（知人ネットワーク×スタック明示）

---

### B案
```
Next.js / Supabase 案件を一緒に進めてくれるエンジニアを探しています（由井辰美）
```

**狙い**: 差出人名を件名末尾に入れることで「顔見知りからのメールだ」という認識が先行し、開封判断が0.5秒早くなる。「一緒に進めてくれる」という協業ニュアンスが、外注募集感より低いハードルで読まれる。紹介目的（「自分ではないが知人がいるかも」）の受信者にも刺さりやすい。

**想定開封率**: 45〜55%（顔感 × 協業ニュアンスの組み合わせ）

**推奨**: B案をメインで使い、件名A案を2〜3週間後のリマインド送信に転用する。

## 4. 送信後のフォロー方針

### 返信が来たとき

**パターン1: 「自分が興味あります」**

```
返信例:
ありがとうございます。
お時間30分ほどいただいて、現在動いている案件の概要を共有させてください。
Zoom または Google Meet でいかがでしょうか。
来週〔曜日〕〔時間帯〕はご都合いかがですか？
```

1on1 でのゴール: スタック確認・稼働可能時間・単価感の擦り合わせ（30分以内に終わらせる）。
話が合ったらその場でStep1（ブログ追加・微修正レベルのタスク）を提示して受けてもらうかどうか確認。

---

**パターン2: 「知人を紹介したい」**

```
返信例:
ありがとうございます、それは大変助かります。
よろしければご紹介いただく前に、紹介先の方のお名前（お名前だけで構いません）を
教えていただけますか。先に簡単に調べてから、改めてご紹介いただく形でお願いできると幸いです。
```

理由: 紹介を受けてから「スタックが合わない」で断るとご紹介者に迷惑が掛かる。先に名前（LinkedInやX）を確認してからご紹介受諾する方が双方のコストが低い。

---

**パターン3: 「今は難しいが気になる」**

```
返信例:
ありがとうございます。
急ぎでないのでご都合のよいタイミングで構いません。
もし状況が変わりましたら、あらためてご連絡ください。
こちらからも数ヶ月後に改めてご連絡するかもしれません、そのときはよろしくお願いします。
```

→ 「数ヶ月後に連絡予定」と明示しておくことで、リマインドが唐突にならない。

---

**パターン4: 返信なし（2週間後）**

2週間後にリマインドを1回のみ送る。件名はA案（`【技術協力のお願い】...`）を使うと「別件」感が出て開封されやすい。リマインド本文は「先日送ったメールの再送になります。お時間あるときに一度ご覧いただければ幸いです」3行程度で完結させる。**2回以上の追撃はしない**。

---

### 1on1 の進め方メモ

面談の構成（30分目安）:

1. **最初の5分**: 事業概要を話す（業種はバラバラ・スタックはNext.js+Supabaseで統一・件数は現在5本動いている、程度の情報量で十分）
2. **10〜15分**: 相手のスタック・直近の稼働状況・副業か本業フリーかを聞く
3. **残り10分**: Step1 タスクの具体例を提示（「まずN-デザインのブログ修正1件・単価3〜5万円から試してみませんか」）→ 受けてもらえるか確認

面談後48時間以内にStep1タスクの詳細（Githubリポジトリ・環境変数の渡し方・コミット規約）をドキュメントにして送る。**面談だけで終わらせない**。
