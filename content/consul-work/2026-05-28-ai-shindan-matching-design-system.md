# 制作物: RebuildMatch — AI診断マッチング デザインシステム指示書

## 用途

Next.js 製 Web サービス「RebuildMatch」の全 UI コンポーネント設計の統一基準。  
外部デザイナー・実装者（Claude / エンジニア）がこれを見れば迷わず作れる粒度で記述する。

---

## 1. デザインコンセプト一文

**「あなたのサイトに潜入した探査官が、証拠を突きつける」**

ターミナルの緑光・スキャンログ・コマンドラインの緊張感を「装飾」として纏いつつ、  
読んでいる人に「これは私のサイトの話だ」と気づかせる辛口の知性が武器。  
機械的な冷たさではなく、ウィットのある探偵事務所の雰囲気を目指す。

### 基本色（既存ブランドから継承）

| 役割 | カラーコード | 使用箇所 |
|---|---|---|
| 背景 最深部 | `#0a0a0a` | ページ背景・最後退 |
| 背景 パネル | `#141414` | カード・モーダル・コンテナ |
| 背景 パネル中 | `#1a1a1a` | ホバー状態・入力フィールド |
| テキスト 主 | `#e6edf3` | 本文・ラベル |
| テキスト 副 | `#8b949e` | 補足・キャプション |
| 顧客 アクセント | `#ff5b4a` | CTA・顧客向け行動ボタン |
| エンジニア アクセント | `#3fb950` | エンジニアカード・登録ボタン |
| 警告 | `#d29922` | 中スコア帯・要注意項目 |
| 信頼 / 検証済 | `#58a6ff` | 実測裏付けバッジ・スコアバー |

### ターミナル探査官 追加色

| 役割 | カラーコード | 使用箇所・理由 |
|---|---|---|
| ターミナル グリーン | `#39d353` | スキャンログの `[OK]`・成功状態の文字。GitHub Contributions の草色と同系で「生きている感」 |
| ターミナル グリーン 暗 | `#1a6b2a` | スキャンログ枠の左ボーダー・背景ティント |
| ターミナル アンバー | `#e3b341` | `[WARN]` ログ行・中リスク |
| ターミナル レッド | `#f85149` | `[ERR]` ログ行・高リスク・既存`#ff5b4a`と近似のため統一可 |
| スキャンライン | `#39d353` opacity 0.06 | スキャン中のオーバーレイ（細横線の走査アニメ）|
| カーソル点滅 | `#39d353` | テキスト末尾のブロックカーソル `█` |

### スコア信号色（4段階）

| 状態 | カラーコード | スコア帯 |
|---|---|---|
| 危険 (Critical) | `#f85149` | 0〜39点 |
| 警告 (Warning) | `#d29922` | 40〜59点 |
| 普通 (Fair) | `#58a6ff` | 60〜79点 |
| 優秀 (Good) | `#3fb950` | 80〜100点 |

### 色の使い分け原則

- **ターミナル緑は「ログ演出」専用**。通常のボタンやリンクに流用しない（エンジニア向け緑 `#3fb950` と混同する）
- **赤は2用途**: 顧客CTAボタン(`#ff5b4a`)・危険スコア(`#f85149`)。意図的に近似させ「問題 = 行動」の連想を作る
- **青は検証・信頼の色として固定**。装飾的な青いボーダーなどに使わない
- 背景パネルより暗い色はレイアウトに使わない（穴が開いたように見える）

## 3. タイポグラフィ

### 2系統の使い分け原則

| 系統 | フォント | 使う場所 |
|---|---|---|
| **Sans-serif（ユーザー向け）** | `Inter, 'Noto Sans JP', system-ui, sans-serif` | 見出し・説明文・スコア数値・エンジニア名・CTA |
| **Monospace（探査官演出）** | `'JetBrains Mono', 'Fira Code', 'Courier New', monospace` | スキャンログ枠・URLラベル・コマンド風テキスト・根拠ゲートバッジ内コード |

### タイプスケール

| 役割 | フォント系統 | サイズ / ウェイト |
|---|---|---|
| ページ見出し H1 | Sans | 36px / 700 |
| セクション見出し H2 | Sans | 24px / 600 |
| カード見出し H3 | Sans | 18px / 600 |
| スコア数値（大） | Sans | 56px / 700 |
| スコア数値（中） | Sans | 32px / 700 |
| 本文 | Sans | 15px / 400 |
| キャプション | Sans | 12px / 400 |
| ログ行 | Mono | 13px / 400 |
| バッジ内テキスト | Mono | 11px / 500 |
| URL入力フィールド | Mono | 15px / 400 |

### 等幅フォントを「使わない」場所（重要）

以下の箇所でモノスペースを使うと「オタク感」が出すぎる。明確に禁止する。

- CTA ボタンの文言
- エンジニアのプロフィール名・専門領域
- スコア数値そのもの
- 法的文言・プライバシーポリシー
- スマートフォン幅 375px 以下の本文

## 4. スキャン / 診断演出の仕様

### URL入力 → 診断実行フロー

```
[1] URL入力フィールド（mono フォント）
    ┌──────────────────────────────────────────────────────┐
    │ > https://example.com_                               │
    └──────────────────────────────────────────────────────┘
    ※ フィールド背景: #141414 / ボーダー: #39d353 1px / 左に ">" プレフィックス固定表示
    ※ フォーカス時: ボーダーを #39d353 で glow (box-shadow 0 0 8px #39d35360)

[2] ボタン押下 → フィールドがロック（readonly + opacity 0.7）
    ボタン文言: 「診断スタート」→ 「スキャン中...」に切り替わる

[3] スキャンログ枠が展開する（下記仕様）

[4] 完了後 → スクロールアニメでスコアセクションへ移動
```

### スキャンログ枠の仕様

```
背景: #0d1117（GitHubダーク相当）
左ボーダー: 3px solid #1a6b2a
フォント: monospace 13px
行間: 1.8
パディング: 20px 24px
最大高: 400px / overflow-y: auto
```

#### 表示するログ行（日本語版・実際に出す10行例）

行は上から時系列順に 150〜400ms 間隔で1行ずつ追記される（タイプライター演出）。

```
> ターゲット確認: https://example.com ............. [START]
> DNS解決 .................................................. [OK]
> HTTPレスポンスコード取得 .................................. [OK]  200
> meta description を抽出中 ........................... [SCANNING]
> title タグ解析 ............................................ [OK]
> 住所情報を検索中 — Googleマップと照合 ................ [SCANNING]
> JSON-LD 構造化データを検索中 ....................... [WARNING] 未検出
> ページ速度スコア取得中 (PageSpeed Insights API) ......... [OK]  62/100
> AI 合議セッション開始 — Claude × GPT 各3ラウンド ....... [OK]
> 診断完了 .................................................. [DONE]
```

#### ログ行のカラー規則

| サフィックス | 色 |
|---|---|
| `[OK]` | `#39d353` |
| `[SCANNING]` | `#58a6ff`（点滅アニメ付き） |
| `[WARNING]` | `#d29922` |
| `[ERR]` | `#f85149` |
| `[START]` / `[DONE]` | `#e6edf3` |
| 数値（200 / 62/100 等） | `#58a6ff` |

#### プログレス表示

ログ枠の最上部に固定で水平バーを表示。

```
  解析中... ████████████████░░░░░░░░  68%
```

- バー色: `#39d353`（充填部）/ `#2d333b`（未充填部）
- ブロック文字 `█` `░` は等幅フォントで描画
- 充填アニメはステップ式（各フェーズ完了で次の段に進む）。連続スクロールは使わない

#### スキャンライン（オーバーレイ演出）

スキャン中のみ有効。スキャンログ枠の背景に1px横線が上から下へゆっくり流れる。

```css
.scanline-overlay {
  background: repeating-linear-gradient(
    to bottom,
    transparent 0px,
    transparent 3px,
    rgba(57, 211, 83, 0.04) 3px,
    rgba(57, 211, 83, 0.04) 4px
  );
  animation: scanMove 3s linear infinite;
}
@keyframes scanMove {
  from { background-position: 0 0; }
  to   { background-position: 0 100px; }
}
```

**診断完了後は即座に演出を停止する**（完了後も動かし続けない。「まだ処理中?」と誤解される）

#### スコアバー CSS 仕様

```
バー全体幅: 200px

- スコア数値そのものは **Sans-serif フォント**。「数字の重み」は serif/mono より sans が読みやすい

## 6. コピーライティングのトーン&マナー

### 原則

**辛口だが敵ではない。「問題に気づかせて、直せる気にさせる」が目的。**

- 問題を指摘するとき: 主語を「サイト」にする。人格攻撃しない
  - NG: 「あなたは何もできていない」
  - OK: 「このサイトは2015年で止まっています」
- ウィットは「クスッ」止まり。「爆笑」を狙わない（企業担当者に見せても恥ずかしくない）
- 専門用語はそのまま書かず、後ろに「( = ○○)」で必ず平易な対訳を添える

### 総合スコア帯別コピー

#### 0〜39点（危険）

```
・「Googleにとって、このサイトは存在していません。」
・「見えないサイトは、どれだけ良いサービスをしていても意味がない。」
・「検索してもらえない。マップに出ない。AIに無視される。三重苦です。」
```

#### 40〜69点（警告〜普通）

```
・「あと一歩のところにいるのに、損をしています。」
・「Googleはあなたの店を知っている。でも、信頼してはいない。」
・「競合が同じ点数なら、先に直したほうが勝ちです。」
```

#### 70〜100点（優秀）

```
・「よくここまで育てた。あとは細部だけです。」
・「上位2割のサイトです。残り1割への道は報告書の中に。」
・「診断をパスしたのは、全体の約20%だけです。」
```

### 4軸別 低スコア時の辛口ワンライナー

#### SEO スコア低 (< 40)

```
・「title すら刺さっていない。Googleは最初の1行で帰ります。」
・「キーワードゼロ。サイトの意図がGoogleに伝わっていない状態です。」
```

#### MEO スコア低 (< 40)

```
・「Googleマップに、あなたの店の住所は正しく登録されていますか?今日確認してください。」
・「近くにいるお客さんが、マップで別の店に流れています。」
```

#### LLMO スコア低 (< 40)

```
・「ChatGPTやPerplexityに『この地域のおすすめ○○』と聞いても、あなたの店は出てきません。」
・「AI検索が普及する前に直しておかないと、2年後に後悔します。」
```

#### JSON-LD スコア低 (< 40)

```
・「構造化データが未設定です。Googleに読んでもらう『目次』がないのと同じです。」
・「リッチリザルト（地図・評価星・FAQの検索表示拡張）が一切出ない設定になっています。」
```

### NG例（使ってはいけないコピー）

| NG | 理由 |
|---|---|
| 「最悪です」「終わってます」 | 侮辱。怒りを生み改善意欲を奪う |
| 「今すぐ無料で解決!」 | 広告臭。信頼を壊す |
| 「〜かもしれません」の多用 | 根拠ゲートに反する。確認済み / 推定を明示する |
| 専門用語の羅列（改善なし） | 読んでも何も分からない。必ず対訳を添える |
| 「絶対に上位表示」 | 法的・倫理的リスク |
| ターミナル演出を多用しすぎるコピー | 「ハッカーに攻撃された?」と誤解される恐れあり |

## 7. 専門用語の平易な対訳表

実装ルール: 専門用語が初出する箇所には必ず `= ○○` をツールチップまたは括弧で添える。

| 専門用語 | 一般向け一言対訳 |
|---|---|
| **SEO** (検索エンジン最適化) | 「Googleの検索結果に出やすくする対策」 |
| **MEO** (マップ検索エンジン最適化) | 「Googleマップに正しく・魅力的に載せる対策」 |
| **LLMO** (AI検索最適化) | 「ChatGPT・Perplexityなど"AIに聞く検索"で推薦されるための対策」 |
| **JSON-LD 構造化データ** | 「Googleに『このサイトは○○の店です』と機械語で伝えるコード」 |
| **リッチリザルト** | 「検索結果に星評価・FAQ・営業時間が表示される拡張表示」 |
| **PageSpeed スコア** | 「Googleが測定するサイトの表示速度の点数（100点満点）」 |
| **クロール** | 「GoogleのロボットがサイトをAI診断するための巡回」 |
| **インデックス** | 「Googleの検索データベースに登録されること」 |
| **実測裏付け ✓** | 「APIやGoogleのデータで実際に確認した指摘」 |
| **要確認 △** | 「サイト内容から推定した指摘。実際の設定確認が必要」 |

## 8. コンポーネント単位の指示

### 8-1. スキャンログ枠 (`<ScanLog>`)

```

  背景: #0d1117
  左ボーダー: 3px solid #1a6b2a
  角丸: 8px
  内側パディング: 20px 24px
  最小高: 180px / 最大高: 400px

テキスト色: #e6edf3 デフォルト（ステータスで上書き）

プレフィックス:
  全行先頭に ">" を #8b949e で表示
  タイムスタンプ（任意）: [HH:MM:SS] 形式で先頭に。色 #8b949e

## 9. やってはいけないこと

### 世界観を壊すNG

| NG演出 | 理由 |
|---|---|
| マトリックス風の緑テキスト滝 | サービス全体が「ゲーム/玩具」に見える。真剣さゼロ |
| 全文 monospace | 読みにくい。等幅は「演出の差分」として効く。全面に使うと単なる苦行 |
| ターミナル枠に3行以上の英語コマンド | 一般ユーザーが置いていかれる。ログは日本語 + ステータス英語の混在で |
| 頭蓋骨・ウイルス・南京錠 のアイコン | セキュリティ侵害サービスと誤認される。サイト診断≠攻撃 |
| エラー画面風の全画面赤 | 壊れたと思われる |
| スキャンアニメが診断完了後も動き続ける | 「まだ処理中?」「重い?」と不安にさせる |
| BGM / 効果音 | 仕事中に開けない。即離脱 |
| スキャン画面のカウントダウン演出（10秒!） | 圧迫感。AIの合議という本物感が消える |

### 企業顧客に出すと危ない演出の線引き

| 演出 | 安全な範囲 | 危険な範囲 |
|---|---|---|
| 辛口コピー | 「このサイトは2015年で止まっています」 | 「こんなサイト恥ずかしくないですか」 |
| ハッカー感 | ログ枠の左ボーダーをターミナル緑にする | 「サイトに侵入しました」という文言 |
| 警告色 | スコアバーを赤にする | ページ全体の背景を赤にする |
| ウィット | 「Googleさえあなたの店を知らない」 | 担当者個人への言及 |

### コピーの自己検閲チェック

診断コピーを追加するたびに以下で確認する。

```
□ 主語は「サイト」「コンテンツ」であり、人格攻撃でない
□ 企業の受付担当者に画面を見せても問題ない
□ 問題の指摘に「直せる」可能性が1フレーズ以上ある
□ 専門用語を使うなら直後に対訳を添えた
```
