## この資料は誰向けか

この資料は、Claude Codeを使ってみたいものの、次のような不安がある人向けです。

- どのフォルダやファイルを触るのか分からない
- 頼んでいない場所まで変わるのが心配
- 修正後に、何を確認すればよいか分からない
- テストという言葉は聞くが、自分の作業で何をすればよいか分からない
- AIから「完了しました」と言われても、本当に終わったか判断できない

最初から大きな機能を作りません。今回は、ボタンの文言修正や説明文の追記など、**結果を自分の目で確認できる小さな修正を1件だけ**扱います。

## 今日できるようになること

- Claude Codeを使う前の前提を確認できる
- 変更前の状態をAIに説明させられる
- 修正内容を1件に絞って頼める
- 変更前と変更後の差分を確認できる
- プロジェクトに合ったテストを実行できる
- 変更内容、確認結果、未確認事項を報告させられる

## まず結論

Claude Codeへ安全に修正を任せる基本は、次の6段階です。

1. 対象と前提を決める
2. 変更前を確認する
3. 修正を1件だけ頼む
4. 差分を確認する
5. テストする
6. 結果を報告してもらう

大事なのは、AIへ「全部いい感じに直して」と頼まないことです。対象、変更内容、触らない範囲、完了条件を短く伝えます。

> Claude Codeが修正できることと、その修正を公開してよいことは別です。最初の練習では、公開、本番反映、外部サービスへの送信、データ削除は頼みません。

## 順番に理解する本文

### 1. 対象と前提を決める

作業を始める前に、次の5点を確認します。

| 確認すること | 例 |
|---|---|
| 作業する場所 | 対象プロジェクトのフォルダ |
| 直したいもの | 予約ボタンの表示文言 |
| 触らないもの | リンク先、色、配置、ほかのページ |
| 完了条件 | 指定した1か所だけ新しい文言になる |
| 確認方法 | 既存テストとローカル画面 |

さらに、次の前提を整えます。

- 元へ戻せるように、Gitまたはバックアップがある
- パスワード、APIキー、個人情報を依頼文へ貼らない
- 本番データを直接変更する作業ではない
- プロジェクトのREADMEや手順書を確認できる
- 自分に変更の権限がある

### 2. Claude Codeを起動する

ターミナルで対象プロジェクトのフォルダを開きます。必要なら、先にバージョンを確認します。

```text
claude --version
```

Claude Codeを始める基本のコマンドは次のとおりです。

```text
claude
```

起動できたら、すぐに修正を頼まず、現在の場所と対象を確認します。

### 3. 変更前の状態を確認する

最初の依頼では、まだ編集させません。

```text
まだファイルを変更しないでください。

次の内容を確認して、短く報告してください。
1. 今いるプロジェクトの目的
2. 予約ボタンが書かれているファイル
3. 現在の表示文言とリンク先
4. この修正に関係するテストや確認方法
5. 変更すると影響しそうな範囲
```

報告を読み、対象ファイルと現在の表示が自分の想定と合っているか確認します。違っていたら、この段階で止めて質問します。

### 4. 修正を1件だけ頼む

対象が分かったら、1件の依頼を出します。

```text
目的:
予約ボタンの意味を初めての人にも分かりやすくする。

対象:
先ほど確認した予約ボタン1か所。

変更:
表示文言を「予約する」から「無料相談の日程を選ぶ」へ変える。

触らない範囲:
リンク先、色、配置、ほかのボタン、ほかのページは変更しない。

完了条件:
対象の1か所だけ文言が変わり、リンク先と見た目は変わっていない。

確認:
変更後に差分を示し、既存の確認方法を実行する。
公開、コミット、プッシュはしない。
```

対象、変更、触らない範囲、完了条件がそろっていると、意図しない変更を見つけやすくなります。

### 5. 差分を確認する

差分とは、変更前と変更後の違いです。Claude Codeの「完了しました」という文章だけで判断せず、実際に変わったファイルと行を見ます。

確認するのは次の4点です。

1. 変更されたファイルは予定どおりか
2. 変更は頼んだ1件だけか
3. リンク先、数値、名前などを誤って変えていないか
4. パスワードや個人情報が追加されていないか

Gitを使っているプロジェクトでは、Claude Codeに「変更したファイルと差分を見せてください」と頼めます。自分で確認する場合は、プロジェクトの運用に合った差分表示を使います。

### 6. テストする

テストは、変更後も必要な動きが保たれているかを確かめる作業です。コマンドを推測せず、README、開発手順、既存の設定から確認します。

Claude Codeには、次のように頼みます。

```text
このプロジェクトで既に使われている確認方法を調べてください。
新しいテスト方法は勝手に追加せず、既存の方法を実行してください。

実行できない場合は、理由と、人が代わりに確認する項目を報告してください。
```

Webページの文言修正なら、少なくとも次を確認します。

- ページが表示できる
- 新しい文言が表示される
- リンク先が変わっていない
- PC幅とスマホ幅で文字が切れていない
- 既存のリンク検査やビルドが通る

### 7. 結果を報告してもらう

最後の報告は、次の形にそろえます。

```text
次の4項目で報告してください。

1. 変更したファイル
2. 変更内容
3. 実行したテストと結果
4. 実行できなかった確認、残っている注意点
```

「成功しました」だけでは足りません。実行した確認と、まだ確認していないことを分けます。

## 具体例 / やってみる

### 練習: 説明文の誤字を1か所だけ直す

自分のプロジェクトで、結果を見て判断できる小さな誤字を1つ選びます。次の依頼文を使ってください。

```text
このプロジェクト内の説明文にある誤字を1か所だけ直します。

まず編集せず、対象ファイル、現在の文章、表示されるページ、
既存の確認方法を報告してください。

私が対象を確認したあと、指定した誤字だけを修正してください。
ほかの言い回し、レイアウト、リンク、画像は変更しないでください。

修正後は、変更ファイルと差分を示し、
プロジェクトに既にある確認方法を実行してください。

コミット、プッシュ、公開はしないでください。
```

次の順番で進めます。

1. 変更前の報告を読む
2. 対象が合っていると確認する
3. 1件だけ修正させる
4. 差分を見る
5. テスト結果を見る
6. 自分の目で表示を確認する

## 用語・出典

### 用語

- **Claude Code**: プロジェクトのファイルを読み、編集し、コマンドを実行できる開発支援ツール
- **ターミナル**: 文字でコマンドを入力してPCを操作する画面
- **差分**: 変更前と変更後の違い
- **テスト**: 変更後も必要な動きが保たれているかを確認する作業
- **Git**: ファイルの変更履歴を記録し、前の状態へ戻しやすくする仕組み

### 必要になってから確認するコマンド

最初の小さな修正で、すべてを使う必要はありません。今日はバージョン確認と起動だけで十分です。

| コマンド | 役割 | 使う時期 |
|---|---|---|
| `claude --version` | インストールされている版を確認する | 起動できない時や資料と表示が違う時 |
| `claude` | 対象フォルダでClaude Codeを始める | 小さな修正を試す時 |
| `claude agents` | 複数のバックグラウンドセッションを一覧で見る | 1件の修正に慣れたあと |
| `/goal` | 完了条件を設定し、その条件まで作業を続ける | 完了条件を自分で判断できるようになったあと |
| `/loop` | 同じ確認を一定間隔で繰り返す | 定期確認が本当に必要になったあと |

コマンドや機能は更新されます。使う直前に公式資料で現在の説明を確認してください。
