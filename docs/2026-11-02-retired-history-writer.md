# 旧Supabase履歴書込の閉止

PR #163 は未統合で、現正本の ArticleStore は旧環境変数だけでSupabaseへ自動接続していた。既存候補の閉止を最新mainへ分離した。

通常のローカルSQLite履歴は同じファイル・新着判定で継続する。旧Supabase変数が残る場合は通信・DB作成前に停止し、自動でSQLiteへ逃がさない。D1はまだ実移送/受入前で選択不可。旧一括移送コマンドは環境・DB・SDKを読まず終了2となる。既存履歴や秘密設定は変更しない。

日次処理を旧変数付きで起動していた場合は履歴保存時に停止するため、担当者は元履歴保全と移送を確認して設定を切り替える。設定を勝手に消さない。SQLite既存経路、再起動後重複判定、旧設定拒否、廃止コマンドの依存なし終了を合成データで検証する。
