# 制作メモ

- 対象：告知・更新・同じ問い合わせへの回答を一人で担う彦根周辺の教室、商店、地域活動の運営者。
- 悩み：本来の仕事の後に、サイト更新や返信が残る。
- 持ち帰る一言：ホームページに、AIが働ける入口を。人には、人と向き合う時間を。
- 行動：よく聞かれる質問を3つ書き出し、最新の答えがサイトにあるか確認する。導入相談時にもこの3問を使う。
- 媒体：AI相談ブログを原本。noteではストーリー中心、SNSでは受付・編集室・仕事場の3役、YouTubeでは既存サイトとAI用の道具の違いを実演できる。
- 実話：Cloudflareの自社ブログ移行（2026-08-12、報告2026-08-24）。冒頭の店・教室は架空の例と明記。由井氏の実績・顧客発言・効率化数値は追加していない。
- 本作業：記事・画像・ローカルプレビューの作成。公開用ディレクトリやCMSレコードは変更しない。
- タイトル・構成の選定：依頼済みの制作を進めるため、AGENTS.mdの実行ファーストに従い、以下の比較を制作側で行って本文まで完成させた。

## 仮タイトル候補（3案）

1. 推奨：ホームページに、AIの受付と編集助手がやってくる。Cloudflare・EmDashで変わる小さな事業の発信
   - 日常の作業と道具の役割が直結する。小規模事業者向け。MCP、EmDash、Cloudflare OSを初めて調べる読者に対応。地域講座の例から3つの質問の整理へ誘導。
2. 「サイトを置くだけでAI対応」はどこまで本当？Cloudflare・EmDashをやさしく整理
   - 誤解の修正を軸にする。すでにニュースを読んだ人向け。導入条件の比較から機能を一つ選ぶ行動へ。未確認の失敗談は作らない。
3. 夜9時半のサイト更新を変えたい。WebMCP・EmDash・Cloudflare OSで始めるAI活用
   - 架空の一場面を起点にする。更新時間を減らしたい運営者向け。製品比較より仕事の流れを主役にし、告知下書き1本を試す。

## H2構成候補（3組）

### A：役割が分かる順（採用）

1. WebMCPは、ホームページに「AIが使える受付」をつくる
2. EmDashは、AIと一緒に記事を育てるためのブログ管理ツール
3. Cloudflare OSは、サイト更新を日々の仕事につなぐAIの仕事場
4. 「置くだけ」の先へ。最初は、よく聞かれる質問を3つ整える

### B：ストーリーから現実の事例へ

1. 問い合わせが残る夜に、AIの受付を想像する
2. Cloudflare自社ブログでは、読むAIと書くAIの入口を分けた
3. 記事と仕事をつなぐには、道具と権限の設定が必要
4. 最初の告知記事を、人が確認する流れで作る

### C：導入前の疑問から答える

1. MCPとWebMCPは何が違うのか
2. EmDashでWordPressを置き換える前に確かめること
3. Cloudflare OSとEmDashは自動でつながるのか
4. 小さな事業が最初に整える情報は3つでよい

## 最終タイトルの判断

本文・H2・画像計画と再照合し、候補1を採用。主役が「製品がすごい」ではなく「運営者の時間」になり、受付と編集助手という二つの使い方を正確に伝えられる。最強、全自動、必ず集客、WordPress終了などの裏付けのない表現は使わない。
