## 目的と採用内容

- 対象: AIエージェント講習を一度以上受講した方、またはCodexを十分に使える事業者。
- 主題: 予約表・顧客/施術/商品リストを先に用意し、日時付きの録音・文字起こしを時間帯で対応させ、確認後に記録へ保存するアプリの開発。
- 持ち帰る一言: 一日の会話を、明日の仕事を助ける記録へ。
- CTA: 2時間の個別講習。LINEで「個別講習希望」と仕事を一言送る。未確認のLINEアカウントURLは作らず、既存の /#contact を補助導線にする。

## タイトルと構成の比較

1. 採用: 10時の会話が、10時のお客様の記録になる。録音を仕事につなぐアプリ — 読者は接客・施術・相談担当者。時間で対応させる仕組みと記録の手間を同時に伝え、個別講習へつなぐ。検索語: 録音、顧客記録、Codex。地域を無理に加えない。
2. 録音は残るのに、顧客メモが書けない。予約表から考えるAI活用 — 記録整理が滞る方へ。失敗からの改善を扱えるが、本人の具体的な失敗実績が未確認なので体験談としては採用しない。
3. 要約の先へ。予約と音声から作る、自分用の顧客記録アプリ — Codex経験者向け。標準の要約と業務連携の違いを説明し、試作と講習へつなぐ。機能説明が先行するので第1案を採用。

構成A（採用）: 予約表を土台に時間帯で結びつける / 顧客履歴と商品改善の例 / 経験者向け2時間講習。
構成B: 一日の終わりに困る記録整理 / 10時・11時の予約と会話 / 次の接客に生かす / 自分用に作る。架空例が長くなるため見送り。
構成C: 文字起こし・要約・顧客保存の違い / 連携できる範囲 / 確認して保存する仕組み / 講習。説明中心になり、楽しさが弱くなるため見送り。

本文完成後もタイトルを再比較し、時間帯対応が最も直感的な第1案を維持。3章は本文の要点を要約し、図4点はすべて概念図。実装済み画面・顧客成果の証拠として扱わない。動画制作の依頼はないため動画は新設しない。

## 根拠と境界

- 運営者本人の説明: 予約・顧客/施術/商品の時系列が先、録音を対応付ける構造、個別講習2時間、受講条件。実装可能な方向として紹介し、導入先や効果数値を創作しない。
- 想定例: Aさん10時/Bさん11時、施術・商談・商品改善。実在顧客の実績ではない。
- SwitchBot公式（2026-10-24確認）: https://www.switchbot.jp/products/switchbot-ai-mindclip — 録音、文字起こし、要約機能。顧客データ保存は製品標準機能と主張しない。
- OpenAI公式（2026-10-24確認）: https://openai.com/ja-JP/codex/ — ソフトウェア開発を支援するCodex。外部連携は対象の保存方法・権限に依存。
- ドメイン不要はローカルのブラウザで使う場合。無料・常時自動・完全識別・2時間で全連携完成を保証しない。
- 録音の了承、閲覧制限、時間ずれ・曖昧な対応の保存前確認を本文に含む。
