# AI相談 管理機能の独立ページ化

## 決定

AI相談の管理機能は、長い一画面やタブではなく、目的別の独立URLで開く。`/admin` は全体状況・件数・監視値を表示しない、管理機能への入口だけにする。

利用者が指定した正式名称は **AI相談** のままとし、恋愛相談への変更は行わない。既存の認証、API、公開ページ、外部投稿・決済・データ更新の承認境界も変更しない。

## 背景と目的

現行の管理機能には、ブログ制作の複数工程、リール制作、SNS投稿、SNS分析、AI相談、運用資料がある。作業中に無関係な情報を見せず、必要な作業だけを直接開けるようにする。

既存の本流にはブログ管理を7つのURLに分割した実装がある。この設計では、その実装を作り直さず、共通メニュー・入口・認証・URLの整合を保つことを優先する。

## 情報設計

### `/admin` — 管理入口

- 全体状況、横断ダッシュボード、集計カード、監視値は置かない。
- 「ブログ管理」「リール制作」「SNS投稿」「SNS分析」「AI相談」「OPS」「公開ページ」「ログアウト」へのリンクだけを表示する。
- 各リンクは、機能名ではなく作業目的が分かる短い説明を添える。

### 独立URL

| 目的 | URL | 方針 |
| --- | --- | --- |
| ブログ工程の入口 | `/admin/blog` | 7工程への入口。作業状態の横断集計は出さない。 |
| 接続確認 | `/admin/blog/status` | ブログ制作に必要な接続だけを確認する。 |
| ブログ設定 | `/admin/blog/settings` | 対象や設定を扱う。 |
| 記事一覧 | `/admin/blog/articles` | 必要なときだけ記事を確認する。 |
| AI生成 | `/admin/blog/generate` | タイトル・本文案の生成だけを行う。 |
| 編集・画像 | `/admin/blog/editor` | 採用案の編集と画像指示だけを扱う。 |
| 公開・取り消し | `/admin/blog/publish` | 公開前の確認と公開操作だけを扱う。 |
| リール制作 | `/admin/apps/reel/` | 既存の専用制作画面を維持する。 |
| SNS投稿 | `/admin/sns-post` | 投稿文、下書き、履歴を扱う。 |
| SNS分析 | `/admin/gubble-sns` | 反応確認と改善だけを扱う。 |
| AI相談 | `/admin/chat` | 運用メモや判断の相談を扱う。 |
| 運用資料 | `/ops` | 資料・プロンプトを扱う。`/admin/docs` は既存どおりここへ誘導する。 |

`/admin/status` は認証済みの保守用診断URLとして残してよいが、管理入口や共通メニューには「全体状況」として表示しない。

## 実装境界

- 認証済みHTMLは既存の `api/admin/*.ts` と `withAdmin` を使って配信する。
- URLの入口は `vercel.json` のrewriteで統一し、未認証時に内容を返さない。
- 共通ヘッダー、PCメニュー、モバイルメニューは `site/static/admin/admin-menu.js`、共通見た目は `site/static/admin/admin-common.css` を唯一の共通源とする。
- ブログの工程間で必要な下書き・編集内容は既存の `sessionStorage` を使い、今回の変更で顧客情報や新しい永続データは保存しない。
- 既存の外部投稿、課金、公開、データ更新の操作は、現在の確認・承認手順を維持する。
- 旧来の大きな `site/static/admin/index.html` を新しい導線から再公開しない。削除は別タスクとし、今回の範囲では機能喪失を招かない。

## 受入条件

1. `/admin` に全体状況・集計・監視値が表示されず、目的別リンクだけが表示される。
2. 上表の各URLから、対応する一つの作業だけを開ける。
3. ブログの7URLでは、現在地が共通メニューで分かり、必要な下書き状態がページ遷移後も維持される。
4. 全管理URLが既存のBasic認証で保護され、未認証では管理HTMLやデータが漏れない。
5. PC幅と390px幅で共通メニューが読め、横方向のはみ出し、スクロールロック不良、ブラウザエラーがない。
6. 既存の公開ページ、SNS投稿、決済、データ保存の挙動を変更しない。

## 検証と公開

- 汚れた主checkoutには書き込まず、最新 `origin/main` から分けた作業ツリーで変更する。
- 管理HTMLの構文、TypeScript、rewrite、リンク、認証応答を確認する。
- 既存ログインセッションを利用できる場合だけ、各管理URLをPC幅・390px幅で確認する。認証情報は取得・表示・保存しない。
- 本番反映時はVercelの成功状態、`/admin` と各独立URLの到達性、共通メニュー、公開ページの非回帰を確認する。
- 実記事公開、SNS送信、決済、顧客データ変更は、この設計だけでは実行しない。

## スコープ外

- AI相談の正式名称・公開サイトの改名
- 恋愛相談ページや恋愛相談機能の追加
- 新規の顧客情報保存、CRM、問い合わせフォーム
- 外部アカウントへの投稿、課金、公開、データ更新の自動実行
