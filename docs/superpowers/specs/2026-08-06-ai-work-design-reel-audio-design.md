# AI時代のワークデザイン：ブログ・Reel・MyBlog標準化設計

作成日: 2026-08-06
承認: ユーザー承認済み（「はい」）
対象: AI相談の記事上部動画、Instagramリール `@climbingconsul`、全事業で使う `myblog` スキル

## 目的

「AIが制作を速くしても、経験をもとに目的・優先順位・責任を設計する人の役割はむしろ重要になる」という記事の結論を、ブログとReelで一貫して伝える。記事は既存の本文を最大限残し、Reelは中央テキストを女性ナレーションが一語も省かず読み上げる。音楽は気分を支えるだけに留め、声と内容の理解を最優先にする。

## 固定する記事方針

- 最終タイトルは **AI時代にデザインは不要になるのか？ むしろ必要になる「経験」と「仕事をデザインする力」** とする。
- 既存の本文、H2、事例、FAQ、CTA、参考資料、画像、URLスラッグ、既存5場面の中央テキストは書き換えない。
- タイトル直下、メタ情報の直後、動画と本文より前に、次の注釈を表示する。

  > AIを思考整理の補助に使い、運営者自身の経験と考えをもとに丁寧にまとめた記事です。

- `authorship_note` は記事ソースのfrontmatterに保持し、表示場所は記事本文に書かずサイトレンダラーが保証する。

## 全事業向けMyBlog標準

1. MyBlogで新規作成または大幅改稿する全記事は、タイトル直下に事実に即した `authorship_note` を置く。
2. 現場経験・運営者の考えが確認できる場合は上記の本人性を示す文面を使う。確認できない場合は、次の安全な文面へ切り替える。

   > この記事は、AIを整理・編集の補助として使い、運営者が内容を確認・編集しています。

3. 「すべて本人が書いた」「ここでしか得られない」など、事実確認できない断定や優位性の表現は使わない。
4. ブログ連動Reelをユーザーが依頼したときだけ、MyBlogはMyReelの承認・公開境界を引き継ぎ、以下の音声要件を制作セットに含める。Reelを依頼していない記事には動画を強制しない。
5. この共通ルールは、`SKILL.md` と `agents/openai.yaml` の双方に反映する。共有Blog App Serverの作業ツリーは既存の大きな未コミット変更があるため、この作業では上書きしない。

## Reelの構成

- 形式: 9:16 / 1080×1920 / 30fps / H.264 + AAC
- 尺: 約28.8秒。速読にせず、各文の末尾に0.15秒以上の余白を残す。
- 声: 日本語女性ナレーション。落ち着きがあり、問いかけは明瞭に、断定し過ぎず親しみを持たせる。
- 原則: 中央の各行をつなげた文が、ナレーション台本と完全一致する。補足は小見出し・キャプション側へ置き、中心メッセージを言い換えない。

| 場面 | 時間 | 中央テキスト | 読み上げ台本 |
| --- | ---: | --- | --- |
| 1: 内容紹介 | 0.0–5.4秒 | AI時代に、デザインは / 不要になるのか？ / 仕事設計の視点から考えます。 | AI時代に、デザインは不要になるのか？ 仕事設計の視点から考えます。 |
| 2: 問い | 5.4–9.4秒 | AIで仕事が / 速くなったのに / なぜ決められない？ | AIで仕事が速くなったのに、なぜ決められない？ |
| 3: AIの役割 | 9.4–14.0秒 | AIが得意なのは / 作る・並べる / 選択肢を増やす | AIが得意なのは、作る、並べる、選択肢を増やす。 |
| 4: 人の役割 | 14.0–18.2秒 | 人が担うのは / 目的・優先順位 / 最後の責任 | 人が担うのは、目的、優先順位、最後の責任。 |
| 5: 対象の広がり | 18.2–23.2秒 | これはデザインだけでなく / すべての仕事の / ワークデザイン | これはデザインだけでなく、すべての仕事のワークデザイン。 |
| 6: 行動 | 23.2–28.8秒 | 任せる・決める・確かめる / 3つに分けて / 明日から使おう | 任せる、決める、確かめる。3つに分けて、明日から使おう。 |

## 音楽とミックス

- 外部楽曲・サンプル・ボーカルは使わず、再生成可能なオリジナルの淡いシンセパッド、控えめなパルス、高域のきらめきだけでBGMを合成する。
- 約92 BPM、0.35秒のフェードイン、0.8秒のフェードアウト。強いキック、耳に残り過ぎるメロディー、声と競合する中域は使わない。
- 女性ナレーションは統合ラウドネス約 -16 LUFS、真のピーク -1.5 dBTP以下を目標にする。BGMはナレーションより十分低く、ナレーション中はさらに約6 dBダッキングする。
- 映像の音声トラックにはナレーションとBGMを混ぜる。`narration.m4a` と `background-music.wav` は監査用の個別音源として残す。

## 実装境界と成果物

1. AI相談のfrontmatterにタイトル、`authorship_note`、約29秒へ更新した動画ラベル・キャプションを追加する。
2. AI相談の静的サイトレンダラーは、ブログに限って注釈をヘッダー直下かつ動画・本文より前に安全にエスケープして描画する。
3. Reelビルドは、場面ごとの可変時間、6場面、完全一致する音声台本、オリジナルBGM、ダッキング、QAメタデータを扱う。
4. ビルド後に動画、カバー、ストーリーボード、プレビュー、投稿マニフェスト、README、音声台本、QAを再生成し、サイトの動画・表紙を同一内容で差し替える。
5. `myblog` スキルは、事実に即した注釈と、依頼時だけのブログ連動Reel音声ルールを必須化する。スキル自体の検証も行う。

## 検証と公開境界

- 単体テストで、注釈がタイトルより後・動画より前に描画されること、非ブログに漏れないこと、Reelの6場面と台本が一致することを確認する。
- 動画は1080×1920、30fps、約28.8秒、H.264/AAC、音声あり、6場面、各場面3行以内を機械確認する。BGMファイルの存在、ミックスに音声があること、ナレーションと画面文の対応表も確認する。
- PC幅と390px幅で、ブログの注釈、動画、横スクロール、動画再生を確認する。Reelはフレーム画像と完成動画を確認する。
- 完成した記事・動画・キャプションをユーザーへ提示し、公開の最終承認を得るまで、本番デプロイ、CMS公開、Instagram投稿、ストーリー、コメントを実行しない。
- Reelを公開した後のストーリー共有とブランドコメントは、既存の二回目承認を維持する。

## MyBlog forward test fix 2（2026-08-07）

- **失敗**: 地域事業者という一般ケースで、固定の5場面/15秒と別事業の `@climbingconsul` を勝手に採用した。
- **対策**: Reelは内容紹介1場面と全文読み上げに必要な可変場面・尺で設計し、投稿先・CTA・ブランド資産・配色・保存先を対象事業プロフィールまたは明示指示からだけ解決する。未解決なら投稿工程に進まず、レビューで語句照合、内容紹介、BGMダッキング、可変尺、事業/投稿先分離、最終承認を確認する。

## MyBlog forward test fix 3（2026-08-07）

- **検出**: 投稿先未確定の停止は機能したが、女性ナレーションに中心テキストの要約・言い換え余地があり、BGMも任意の市販曲選定へ流れた。
- **対策**: 各場面で `center_text` / `narration_text` 対応表を残し、改行・句読点・中黒の自然化以外は完全一致にする。内容紹介も独立した中心テキスト場面にし、結論だけ同じ補足音声を禁止する。BGMは再生成可能な自作/保有オリジナル非ボーカルを標準とし、第三者音源は事業者が特定の利用権・出所を明示承認した例外に限る。監査資料とQAで音源種別・出所・権利・ダッキング、語句照合、内容紹介、可変尺、事業分離、最終承認を確認する。
