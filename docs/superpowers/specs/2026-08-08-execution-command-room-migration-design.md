# 実行司令室からAI相談管理ページへの完全移行 設計

日付: 2026-08-08  
状態: 設計承認済み、実装前

## 目的

実行司令室の管理機能を、AI相談の管理ログイン配下に独立した管理ページとして移す。移行対象には、課題・事業・AI指示・実行履歴、Googleカレンダーの予定件数、相場羅針盤の取引記録・市場データ、制作画面、PC上のCodex連携を含める。

移行完了後は、実行司令室の公開Sitesプロジェクトとローカルフォルダを削除できる状態にする。顧客情報、認証情報、APIキー、移行用トークンは公開ソース、静的HTML、Git履歴、ログへ含めない。

## 対象範囲

### AI相談側の独立ページ

- `/admin/command-center`: 移行後の管理入口。既存の「全体状況」ページを再作成せず、必要な管理導線と現在操作への入口に限定する
- `/admin/command-center/calendar`: 課題期限とGoogle予定件数のカレンダー
- `/admin/command-center/tasks`: 課題の検索、状態更新、追加
- `/admin/command-center/businesses`: 事業一覧と事業別課題への導線
- `/admin/command-center/directives`: AI指示、承認待ち、実行結果
- `/admin/command-center/studio`: ブログ・リール制作とCodex実行の入口
- `/admin/command-center/tools`: 制作・運用ツールの入口
- `/admin/command-center/trade`: 相場データ、取引計画、取引記録

既存のAI相談管理ページ（ブログ、リール、SNS、OPS）は重複実装せず、必要な場合は上記の制作入口から既存の保護ページへ遷移させる。`/admin/status` は新しいメニューに追加しない。

### 移行するAPI機能

- ダッシュボード取得と課題・AI指示・実行履歴・取引計画・取引記録の更新
- Googleカレンダーの `busy_only` 日別件数取得
- 市場データ、AIブリーフ、AIランキング、接続状態確認
- Codex App Serverのペアリング、実行要求、承認、割り込み、実行結果取得

## アーキテクチャ

### 認証境界

AI相談の既存 `withAdmin` 管理ログインを、すべての新規HTML/APIの入口に適用する。ブラウザにはサービス用共有トークンを渡さない。未認証のHTML要求はログインへ遷移し、未認証のAPI要求は401を返す。

CodexブリッジのHMAC、タイムスタンプ、nonce、ペアリングコード、HttpOnly cookieの境界は維持する。秘密値はAI相談のホスティング環境とPC側のローカル環境変数だけで管理する。

### 永続データ

AI相談側の管理API専用Supabase領域に、公開Data APIから分離したスキーマを作る。サービスロール以外のロールにはアクセスを付与せず、RLSを有効化する。既存の顧客・認証系テーブルには変更を加えない。

移行対象の論理テーブルは次のとおり。

- `projects`
- `tasks`
- `directives`
- `directive_executions`
- `trades`
- `trade_plans`

旧D1のID、作成日時、更新日時、状態、実行履歴、取引記録を保持する。実行履歴には旧環境の `owner_id` を保持し、取引データには移行元の所有者境界を付与する。

Codexブリッジのペアリング状態、nonce、待機中リクエストなどの一時テーブルは移行しない。新環境の初回接続時に再生成し、旧環境の認証状態を引き継がない。

### Googleカレンダー

AI相談側の管理APIがICSをサーバー側で取得し、指定期間の日別件数だけを返す。予定名、本文、参加者、場所、URL、ICS原文は保存・表示しない。応答には `privacy: "busy_only"` を含め、取得失敗時も空の日別件数と利用不能状態だけを返す。

### 市場データとAIプロバイダー

市場データとAIブリーフ・ランキングは、既存のAPI境界をAI相談側の管理APIへ移す。Alpaca、Alpha Vantage、Finnhub、OpenAI、xAIの値は環境変数からのみ読み込み、画面には接続済み・未設定の状態だけを表示する。キーの値、完全なエラーレスポンス、リクエスト本文をログへ出さない。

### PC上のCodex連携

`app-server` のローカルブリッジをAI相談側のソースに移し、作業対象プロジェクトの許可リストとローカル設定をGit管理外へ置く。ブリッジの接続先をAI相談側のAPIへ変更し、旧実行司令室SitesのリレーURLを参照しない。Codexの実行・承認・ファイル変更要求は従来どおり画面上で明示的に確認する。

## データ移行手順

1. 移行前に旧D1の対象テーブルを読み取りエクスポートし、旧フォルダ外の保護されたバックアップ領域へ保存する。バックアップには秘密値を含めない。
2. AI相談側に管理API専用スキーマとRLSを作成する。作成後にセキュリティアドバイザーとテーブル権限を確認する。
3. 一時的なサーバー間移行認証を環境変数で設定し、旧APIから必要な列だけを取得する。移行用認証値はソース、URL、ログ、画面へ出さない。
4. 新スキーマへ冪等インポートする。再実行時は同じIDを上書きせず、差分と競合を検出して停止する。
5. テーブルごとの件数、ID集合、更新日時、正規化ハッシュを比較する。差分がある場合は切替へ進まない。
6. AI相談側の管理APIを新データへ切り替え、旧APIへの参照と旧URLをソース検索で除去する。
7. 旧側を読み取り専用または停止状態にし、最終バックアップを作成する。

## 検証計画

### 自動検証

- 管理ページ/APIの未認証、認証済み、HTTPメソッド、エラー応答
- 移行スキーマの型、必須列、ID重複、冪等インポート
- `busy_only` 契約が予定タイトル・参加者・本文を返さないこと
- CodexブリッジのHMAC、nonce再利用拒否、許可Origin、ペアリング期限
- 市場データとAIプロバイダーのキー値がレスポンスやログに現れないこと
- AI相談側の既存テスト、TypeScript型検査、ビルド
- 実行司令室側の `npm.cmd test` とブリッジのスモークテスト

### 本番確認

- AI相談の管理ログインから全独立ページへ到達できること
- 課題、AI指示、実行履歴、取引計画、取引記録を読み書きできること
- カレンダーが日別の「予定あり」件数だけを表示すること
- Codex連携のペアリング、実行、承認、結果取得、割り込み
- PC幅とiPhone幅でメニュー、表、横スクロール、CTAが破綻しないこと
- 未認証の公開URLから管理データが取得できないこと
- AI相談側本番に旧Sites URL、旧API、旧D1参照が残っていないこと

## 切替・削除ゲート

次のすべてを満たすまで、旧プロジェクトと旧フォルダを削除しない。

- 本番の全管理ページ/APIとCodex連携が検証済み
- D1と新データの照合が一致
- 旧ソース、未保存変更、エクスポートの復元用バックアップを旧フォルダ外へ保存済み
- 旧URL依存と旧API呼び出しが除去済み
- 旧側を読み取り専用または停止状態にした
- 削除直前に対象を再確認した

削除対象は、Sitesプロジェクト `appgprj_6a55fc699ca08191af60b3d6490a9233` とローカルフォルダ `C:\Project\実行司令室` に限定する。Sitesにプロジェクト削除操作が提供されない場合は、停止またはアクセス無効化までを実行し、削除済みとは報告しない。ローカルフォルダは絶対パスを再解決してから削除する。

## 非対象

- 顧客情報、認証情報、予約・決済情報の移行
- 公開ページへの管理データ表示
- 旧環境のペアリングセッションや一時リクエストの引き継ぎ
- 新たな全体状況ページの追加
- 旧Sitesプロジェクトを削除する前の無検証なデータ削除
