# AI相談トップページ：迷ったら60秒診断をヒーロー導線へ統合

**作成日:** 2026-08-08
**対象:** `site/build_portal.py` が生成する公開トップページ (`/index.html`)

## 背景

「迷ったら60秒診断」は、講習・無料相談・個別相談・伴走支援のどこから始めるかを決める入口として既に実装されている。

現行の公開トップでは、診断モーダルと診断用JavaScriptは出力されている一方、起動ボタンがコース一覧の下とコース末尾に分散している。初めて訪れた人は、告知・集客・事務・サイト改善という身近な悩みと診断を結び付けにくい。また、診断結果の旧「この講座を見る」処理は、現行フォーカス版トップに存在しない `.packages-grid` を対象にしており、対象コースの強調表示が成立しない。

本変更は、診断をヒーローの主導線へ移し、診断から実在する無料相談予約またはコース一覧へ確実につなげる。

## 目的と対象者

- **対象者:** 彦根・滋賀の中小事業者、個人事業主、地域団体、学校・福祉の担当者など、AIに関心はあるが最初の一歩を決められない人。
- **解決する悩み:** 「AIが分からない」「告知や集客が苦手」「事務が重い」「サイトや予約導線を整えたいが、どの支援を選べばよいか分からない」。
- **行動目標:** 3問に答え、提案された次の一歩を確認してから、無料相談の日程選択またはコース一覧の閲覧へ進める。
- **媒体上の役割:** Webトップを起点に、講習・相談・資料・後続のSNS告知で共通利用できる「迷ったら60秒診断」という短い入口を作る。

## 採用する方針

### 1. 最新のヒーロー構成を保ち、診断を主CTAにする

最新の `origin/main` にある以下の要素は保持する。

- 地域対象を示す `彦根・滋賀の中小事業者向け`
- 見出し `AIエージェントを、強力なスタッフに。`
- 6%の訴求、3原則、背景画像、既存の配色と動き

既存の `.focus-actions` を、次の優先順位に置き換える。

1. 主CTA（診断を開始）
   - 表示: `迷ったら60秒診断をはじめる →`
   - 実装: `href="#packages"` を持つ `.diagnose-open` アンカーにする。JavaScriptが利用できる場合は遷移を止めてモーダルを開き、利用できない場合はコース一覧へ進める。
2. 診断補足
   - 見出し: `何から始めるか、1分で見える。`
   - 本文: `3問で完了。結果を見てから、予約するか決められます。`
3. 補助CTA（予約を急ぐ人向け）
   - 表示: `無料相談の日程を選ぶ`
   - リンク: 既存の `CONSULT_BOOK_URL`。新しいURLは作らない。
4. 補助リンク
   - 既存の `受講資料 →` は残す。

ヒーロー本文は、次のコピーへ更新する。

> 告知・事務・集客に追われる方へ。AIが気になるけれど、何から始めるか迷う方へ。3つの質問で、いまの仕事に合う次の一歩を提案します。

PCでは診断CTAを最初に置き、予約CTAと資料リンクを同じアクション群に収める。iPhone幅では診断CTA、補足、予約CTA、資料リンクの順に縦並びにし、押し間違いと横スクロールを防ぐ。

### 2. 診断は「使える技術」ではなく「仕事の悩み」から始める

モーダルの見出しを `迷ったら60秒診断`、補足を `いまの仕事に合う入口を、3つの質問で整理します。` にする。

質問はすべて専門用語なしで表示する。

1. **いま一番近い悩みは？**
   - AIを使う前に、何から頼めるか知りたい
   - 告知や集客を、もっと伝わる形にしたい
   - 事務や返信にかかる時間を減らしたい
   - サイト・予約・業務の流れを整えたい
2. **今日、どこまで進めたい？**
   - まず話して、優先順位を決めたい
   - 投稿文や画像などを一つ作りたい
   - 自分用の手順にして残したい
   - 関係者と進め方を決めたい
3. **最初の一歩は、どう進めたい？**
   - 無料相談で入口を整理したい
   - 講習で作りながら学びたい
   - 対面・オンラインで相談したい
   - 長く使える仕組みにしたい

回答は、`start`、`promotion`、`office`、`flow` の4つの推奨タイプに集計する。旧来の `beginner`、`intermediate`、`implementation`、`advanced` と、Codex理解度を前提とする質問文は残さない。

### 3. 結果は次の行動と成果を先に示す

結果表示は「あなたは○○タイプ」ではなく、以下のように次の一歩を先頭に置く。

| タイプ | 次の一歩 | 成果の説明 |
|---|---|---|
| `start` | まずは、任せたい仕事を一つ決める | 今の課題を聞き、AIに頼む最初の仕事と進め方を一緒に整理する。 |
| `promotion` | 告知・集客の型を一つ作る | 誰に何を伝えるかを決め、投稿文・画像・次回の告知手順まで形にする。 |
| `office` | 重い事務を一つ軽くする | 返信、要約、報告、引き継ぎなどから一つ選び、確認できる手順にする。 |
| `flow` | サイト・業務改善の道筋を決める | 予約、問い合わせ、更新、業務の流れを整理し、残すものと直す順番を決める。 |

各結果には必ず次の2導線を出す。

1. 主CTA: `無料相談の日程を選ぶ` → `CONSULT_BOOK_URL` を新しいタブで開く。
2. 補助CTA: `講習・相談コースを見る` → `#packages`。

これにより、診断結果が個別のカード強調に依存せず、常に有効な予約・比較導線になる。旧 `.packages-grid` のフィルター処理と `data-focus-level` は削除する。

### 4. 既存の散在CTAは重複させない

`_render_compact_course_cards()` 末尾の「60秒診断｜無料相談・個別相談・講習・伴走のどれ？」と、コース末尾の `course-quick-actions` 内の診断ボタンは削除する。コース末尾には受講資料へのリンクだけを残す。

これにより、診断はトップで迷いを解く入口、コース一覧は比較と予約をする場所、という役割を分ける。

## アクセシビリティとエラー時の扱い

- 診断開始CTAはアンカーにして、JavaScriptが停止していても `#packages` へ到達できるようにする。
- JavaScriptがある場合は `preventDefault()` を行ってモーダルを開く。
- モーダル本文は `aria-live="polite"` とし、STEP・質問・結果の更新を読み上げ可能にする。
- 開始時に起動元を保存して閉じた後にフォーカスを戻す。閉じるボタン、背景クリック、Escキーを同じ閉じる処理へ接続する。
- `prefers-reduced-motion` の既存配慮を保ち、診断CTA自体へ必須の動きを追加しない。
- 予約URL、価格、コース名、決済・LINE参加条件は変更しない。

## 変更対象

- `site/build_portal.py`
  - `_render_hero_focused()` のコピー、CTA順、診断補足、予約URL。
  - `FOCUSED_PORTAL_CSS` のヒーロー内診断CTA・補足のPC/iPhoneレイアウト。
  - 診断モーダルの見出し、補足、`aria-live` 属性。
  - 診断JavaScriptの質問・結果データ、実在リンク、フォーカス復帰、Escキー処理、不要なカード強調処理の削除。
  - コース一覧とクイックアクションに残る重複診断CTAの削除。
- `tests/test_hero_60sec_diagnosis.py`（新規）
  - ヒーロー内の主CTA、補足、予約URL、CTA順を検証する。
  - 重複CTAが生成HTMLに残らないことを検証する。
  - 診断の見出し、3問、4つの結果、実在する予約・コース導線を検証する。
  - no-JSフォールバック、Escキー、フォーカス復帰に必要なJavaScript契約を検証する。
- `site/dist/index.html`（生成物）
  - `site/build_portal.py` の再生成結果のみを反映する。

## 変更しないもの

- 現行ヒーローの地域表示、見出し、6%訴求、画像、3原則、色設計。
- `CONSULT_BOOK_URL`、各コースの予約先、料金、Square決済、オンラインサロン、受講資料、管理画面。
- SNS投稿、ブログ、外部アカウント、データベース。

## 受け入れ条件

1. 生成されたヒーローの最初の主要CTAが `迷ったら60秒診断をはじめる →` であり、診断補足と無料相談の予約CTAが隣接している。
2. 診断を開始すると、身近な仕事の悩みから始まる3問が表示され、回答後に4種類の次の一歩のいずれかが表示される。
3. 結果の主CTAが `CONSULT_BOOK_URL`、補助CTAが `#packages` を指す。存在しない `.packages-grid` の強調処理には依存しない。
4. JavaScript無効時は主CTAがコース一覧へ遷移し、JavaScript有効時はモーダルを開く。Esc・背景・閉じるボタンで閉じ、起動元へフォーカスが戻る。
5. 1440px前後と390px前後で、ヒーローのCTA、補足、メニュー、画像に横スクロール・低コントラスト・押しにくい要素がない。
6. 既存の予約先、料金、コース一覧、資料リンクは変わらない。

## 検証計画

1. 失敗する `tests/test_hero_60sec_diagnosis.py` を先に追加し、ヒーロー配置・コピー・診断導線を検証する。
2. `site/build_portal.py` を再生成し、追加テストと全 `unittest` を実行する。
3. ローカルでPC幅（1440px前後）とiPhone幅（390px前後）を確認する。主CTA、診断の3ステップ、結果の2導線、Esc、フォーカス復帰、横スクロールを確認する。
4. 意図したソース・テスト・生成物だけをコミットし、`main` へpushする。
5. Vercelの本番 `https://ai-hub-jp.vercel.app` で、同じヒーローコピー・診断・予約URL・PC/iPhone表示を確認する。

## 実装しない代替案

- 既存のコース一覧に診断ボタンを残し、ヒーローにも同じボタンを足す案は採用しない。入口が複数になり、主導線が弱くなるため。
- Codexの理解度だけを問う旧質問を残す案は採用しない。告知、集客、事務、サイト改善から来る初めての利用者の悩みを拾えないため。
- 結果から存在しない `.packages-grid` を絞り込む案は採用しない。結果の主導線を実在する予約URLとコース一覧に固定する。
- 新しい診断サービス、外部フォーム、計測基盤は追加しない。既存の静的HTML・JavaScriptだけで完結させる。

## 設計セルフレビュー

- **未記入確認:** 仮置きの要件や未確定URLは残していない。予約先は既存の `CONSULT_BOOK_URL` を使う。
- **整合性確認:** ヒーロー、診断モーダル、結果CTA、テスト、PC/iPhone検証、Vercel本番確認が同じ導線を検証する。
- **スコープ確認:** 公開トップの診断配置とコピーに限定し、料金・決済・外部投稿・管理画面には触れない。
- **曖昧さ確認:** 結果の主CTAは全タイプで無料相談予約、補助CTAは全タイプでコース一覧と明示した。
