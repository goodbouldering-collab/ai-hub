# AI相談トップ：コース感想のプルダウン化、サロン仮運用表示、自然スクロール

**作成日:** 2026-08-12
**対象:** `site/build_portal.py` が生成する公開トップページ

## 背景と目的

公開トップには、AIエージェント講習・AI個別相談・AI伴走支援・AIコーディングの感想が、コース一覧から離れた独立セクションとして掲載されている。比較中の利用者が、そのコースの内容と感想を同じ場所で確認できる構成へ改める。

AIオンラインサロンは正式開始前の仮運用段階であり、現在の登録者はテスト運用に協力している。この事実を明示しながら、Squareの月額決済と参加導線は利用できる状態を維持する。

また、ヒーロー付近で最初の縦スクロールが一度引っ掛かる体感をなくし、PCとiPhoneのどちらでもページ下部まで自然に連続スクロールできるようにする。

## 対象者と行動

- **対象者:** AIが初めての人、業務改善を検討する地域事業者、各コースを比較する担当者、オンラインサロンの先行参加を検討する人。
- **解決する悩み:** コースと感想が離れて比較しにくい、サロンが正式運用中か分からない、トップでスクロールが引っ掛かる。
- **行動目標:** 各コース内で内容と感想を確認し、必要な申込・予約・決済へ迷わず進める。
- **媒体上の役割:** Webを正本とし、SEO・LLMOから来た利用者にも、現状、体験、申込方法を同じ情報として伝える。

## 採用する設計

### 1. 感想は各コースカード内の2つ目のプルダウンへ移す

4つのコースカードは次の順序にする。

1. コース概要
2. `メリット・内容・参加方法を見る`
3. `受講された方の感想を見る`
4. 申込・予約CTA
5. 受講資料リンク

感想用の`<details>`は、既存の詳細プルダウンと同じ操作・見た目を基礎にし、コースごとの感想3件を表示する。感想のタイトル、本文、匿名表記、12件という総数は変更しない。

現在の独立した大きな感想セクションは削除する。既存URLとの互換性を保つため、`#course-voices`はコースメニュー全体、`#voice-ai-agent`、`#voice-ai-consultation`、`#voice-ai-support`、`#voice-ai-coding`は各感想プルダウンへ引き継ぐ。古いハッシュURLで移動すると、該当コースの「感想を見る」行が表示される。

### 2. SEO・LLMOと構造化データを維持する

感想本文は閉じた`<details>`内にも通常のHTMLとして出力し、利用者が展開して読める状態を保つ。既存のCourse、Service、ReviewのJSON-LDは同じ感想データを参照し、次を維持する。

- 4コース、各3件、合計12件
- 評価点や星の捏造を行わない
- 表示本文とJSON-LD本文を一致させる
- 実名を追加せず、既存の匿名表記を維持する

### 3. AIオンラインサロンは「近日開始・仮運用中」と明示する

サロンの主要見出しを `AIオンラインサロン｜近日開始` に変更する。カード上部の状態ラベルは、正式開催中と誤解される `ライブトーク開催` ではなく `現在は仮運用中` とする。

概要には次の事実を簡潔に記載する。

> 正式開始に向けて現在は仮運用中です。登録中の方にはテスト運用へご協力いただいています。

Square月額決済フォーム、月額2,200円、毎月自動更新、決済後のLINE参加案内は維持する。CTAは決済可能であることと先行参加であることが同時に伝わる `Squareで決済して仮運用に参加 →` とする。

ページ説明、FAQ、Course/Serviceの構造化データでも正式開始前であることを一致させる。決済API、価格、更新条件、LINE招待の秘密情報や実装は変更しない。

### 4. ヒーローはブラウザ標準の縦スクロールへ戻す

調査時点で縦方向の`scroll-snap`や、wheel/touchを`preventDefault()`する処理は存在しない。一方、`html, body`の`overflow-x: hidden`は縦方向を計算上`auto`にし、ルートスクロールの扱いを不必要に複雑にしている。また、ルートの`scroll-behavior: smooth`とヒーローの初期`fade-up`は、ページ表示直後の操作に不要な動きを加える。

次の変更で、スクロールをブラウザ標準の単一縦スクロールにする。

- `html, body`の横方向制御を`overflow-x: clip`へ変更し、縦方向の独立スクロール領域を作らない。
- ルートの`scroll-behavior`を`auto`にして、アンカー移動を含む強制的なスムーズ移動をやめる。
- ヒーロー本文から初期`fade-up`を外し、表示直後から完成状態にする。
- ヒーローの背景装飾は残すが、wheel/touchイベントや固定・スナップ処理は追加しない。
- メニューを開いている間だけスクロールを止める既存制御は維持する。

## エラー時とアクセシビリティ

- `<details><summary>`の標準キーボード操作を使い、独自JavaScriptへ依存しない。
- JavaScriptが無効でも、感想、サロン説明、決済フォームを利用できる。
- 感想の展開前後で横スクロールを発生させない。
- Square APIが失敗した場合の既存エラー処理は変更しない。
- 既存アンカーを削除せず、外部リンクや検索結果からの到達を壊さない。

## 受け入れ条件

1. 4つの各コースカードで、既存詳細の直下に `受講された方の感想を見る` があり、展開すると該当コースの感想3件だけが表示される。
2. 感想12件の文章は変更されず、独立した大きな感想セクションは表示されない。
3. Review JSON-LDは12件のままで、表示本文と一致し、評価点を追加しない。
4. サロン見出しが `AIオンラインサロン｜近日開始` となり、仮運用中、登録者がテスト運用に協力中であることが表示される。
5. サロンのSquareフォームはPOST先を維持し、月額2,200円・毎月自動更新・LINE案内が残る。
6. PCとiPhoneで、最初のwheel／スワイプからスクロール量が増え、ヒーロー境界で強制停止せず、ページ下部まで連続して移動できる。
7. PC幅と390px幅で、閉じた状態はコンパクトで、展開時にも横スクロール、低コントラスト、操作不能がない。
8. 本番URLで表示、感想展開、サロン状態、Square決済フォームの送信先、JSON-LD、コンソールエラーを確認できる。
