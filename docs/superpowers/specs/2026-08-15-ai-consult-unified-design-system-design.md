# AI相談 統合デザインシステム — 設計仕様

作成日: 2026-08-15
対象: 公開トップ、共通管理ナビゲーション、Blog制作、Reel制作、Command Center

## 1. 目的

AI相談の最新公開トップを見た目の基準にし、公開側と管理側を「困りごとを整理し、次の一歩を選び、実行結果を確かめる」一つの体験として整理する。対象者は彦根・滋賀の中小事業者、学校・福祉施設、個人事業主、若い挑戦者と支援者。専門用語やツール名から入らず、時間不足、告知負担、事務作業、集客、学び直しの不安から行動へ案内する。

## 2. 体験原則

1. **困りごとを先に示す** — 機能名より「何が楽になるか」を先に伝える。
2. **一画面一つの主行動** — 主CTAは青、補助行動は白、危険操作は赤系に限定する。
3. **現在地と次の一手を並べる** — 管理画面では状態、次の操作、完了条件を同じ領域に置く。
4. **作成と公開を分ける** — 下書き、確認待ち、公開準備、公開済みを色だけに頼らず言葉と形で示す。
5. **小さく試し、確かめ、残す** — 地域支援・教育の現場で再現できる手順と判断根拠を残す。

## 3. 情報階層

### 公開トップ

`身近な悩み → 60秒診断 → 講習・相談の選択 → 支援例/資料 → 予約`

- 第1CTA: 「迷ったら60秒診断をはじめる」
- 第2CTA: 「AIエージェント講習を見る」
- 第3導線: 受講資料
- 実績は自慢ではなく、支援例・改善前後・現場での学びとして扱う。

### 管理画面

`現在地 → 対象の仕事 → 作成 → 確認 → 保存/公開`

- 固定メニューは既存の共通管理ヘッダー一つに限定する。
- Blog/Reelは共通の制作コマンドバーを使い、APIキー、接続状態、制作切替を同じ位置に置く。
- Command Centerは「指令室」として状態把握を優先し、詳細機能はローカルナビに分ける。
- 390pxでは固定ヘッダーを共通ドロワーへ置き換え、主操作は横スクロールに埋めない。

## 4. Foundations

### 色

| 意味 | 基準値 | 用途 |
|---|---:|---|
| Brand 600 | `#4261C7` | 主CTA、現在地、リンク |
| Brand 700 | `#3E58B8` | hover、強調文字 |
| Ink | `#172033` | 本文、見出し |
| Muted | `#606D83` | 補足、メタ情報 |
| Canvas | `#F8FBFF` | ページ背景 |
| Surface | `#FFFFFF` | カード、入力面 |
| Line | `#DCE4F2` | 境界 |
| Success | `#146C5A` | 完了、接続済み |
| Warning | `#805C13` | 確認待ち、注意 |
| Danger | `#A23A4C` | 失敗、破壊的操作 |

本文と背景、主CTAと白文字はWCAG AAを満たす組み合わせに限定する。状態は色だけで伝えず、ラベル、アイコン、説明文を併用する。

### 文字・余白・形

- 本文: `Inter`, `Noto Sans JP`, system sans。最小本文14px、操作ラベル12px以上。
- 見出し: 画面幅に応じた `clamp()`。日本語本文は行高1.65〜1.8。
- 余白: 4px基準。主要間隔は8 / 12 / 16 / 24 / 32 / 48 / 64px。
- 角丸: 操作8px、カード12〜16px、pill 999px。
- タップ領域: 原則44px以上。フォーカスリングは3pxで常時視認できる。

## 5. 共通コンポーネント

- `Action`: primary / secondary / quiet / danger。default / hover / focus / disabled / loading。
- `Field`: label、任意説明、入力、エラー、保存状態を一組にする。
- `Status badge`: neutral / progress / success / warning / error。文言を必須にする。
- `Card`: heading、要約、状態、主行動の順。カード全体リンクは一つだけ。
- `Shared admin header`: ブランド、現在地、主要7画面、390pxドロワー。
- `Studio command bar`: Blog/Reelの切替、接続状態、APIキー、補助説明。
- `Local navigation`: Command Center内の詳細画面。現在地に `aria-current="page"`。
- `Feedback`: loadingは進行内容、emptyは次の入力、errorは原因と再試行、successは完了内容を示す。

## 6. 画面別契約

| 画面 | 最初に分かること | 主行動 | 完了の見せ方 |
|---|---|---|---|
| 公開トップ | 自分の悩みが対象か | 60秒診断 | 合う支援と予約導線 |
| Blog制作 | 調査から下書きまでの現在地 | 次の制作ステップ | プレビューと保存先 |
| Reel制作 | 元情報・素材・投稿先 | 企画を3案作る | 9:16確認と承認状態 |
| Command Center | 今日の状態と未完了 | 対象タスクを開く | 成功/欠損/要確認 |
| 共通管理ナビ | 現在地と移動先 | 対象画面へ移動 | `aria-current` とパンくず |

## 7. Responsive / Accessibility

- PC: 1280pxを基準。主要コンテンツは最大1400px、Command Centerは1240px。
- Mobile: 390×844を基準。横幅超過を禁止し、2列フォームを1列化する。
- キーボード: Tab順、Escapeでメニューを閉じる、フォーカスを見失わない。
- 動き: `prefers-reduced-motion` で装飾アニメーションを停止する。
- HTML: `main`、`nav`、見出し順序、`aria-live`、`aria-current`、明示labelを使う。
- 認証ページ/管理画面は `noindex,nofollow` を維持する。

## 8. 実装上の正本

- `site/static/design-system/tokens.css`: 全画面共通の意味トークン。
- `site/static/design-system/index.html`: 公開可能なデザイン参照ページ。
- `site/static/design-system/design-system.css`: 参照ページと標準コンポーネントの例。
- `site/build_portal.py`: 公開トップの構造と公開側コンポーネント。
- `site/static/admin/admin-common.css` / `admin-menu.js`: 管理側共通シェル。
- Blog/Reel/Command Center固有CSSは共通トークンの別名だけを持ち、新しい色の正本を作らない。

## 9. 判断根拠

- 最新公開トップは既に、一般の人が理解しやすい悩み起点と明確な青いCTAを持つため、全面置換せず基準として形式知化する。
- 管理側に積み重なった色名を意味トークンへ変換すると、画面を壊さず段階的に統合できる。
- デザイン参照ページを同じ本番ビルドへ含めることで、実装と仕様の乖離を画面で検出できる。
- Blog/Reelは制作手順、Command Centerは運用判断と目的が異なるため、レイアウトを同一化せず、色・操作・状態・ナビゲーションの文法を共通化する。
