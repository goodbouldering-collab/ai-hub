WHY NOW

操作の早さより、
使い方を選べる力を。

文章や絵の案がすぐに出てくると、子どもの「やってみたい」を形にしやすくなります。一方で、もっともらしい間違いを信じたり、考える前に答えを任せたりすることもあります。

だからAI相談キッズは、完成した作品だけでなく、どんな問いを立て、何を確かめ、自分でどこを変えたかを大切にします。今の必要性は、将来への不安をあおることではなく、家庭で判断するための共通体験をつくることにあります。

これからのAIと子どもの関係を、私たちはこう考えます。

AIは発想や下調べを手伝う道具。体を動かす経験、人との対話、自分の判断と組み合わせて使います。どの道具が主流になっても役立つ、問い・確認・表現の習慣を育てたいと考えています。これはAI相談の教育方針であり、将来の成果を保証するものではありません。

FIRST WORKSHOP / 講習シナリオ案

90分で、ひとつの「できた」を。

テーマは「身近なものから、自分だけの発見カードをつくろう」。葉っぱ、野菜、自分で描いた絵などを題材にします。初回は小学1〜6年生と保護者、3〜4組の少人数を想定。年齢差が大きい場合は、低学年・高学年で回を分けます。

  1. 0–10分

    好きなものをひとつ選ぶ

    講師「今日は何をつくりたい？ まず、自分の目で気づいたことを三つ教えて。」

    子どもは実物を見て、色・形・気になる点を紙に描く。保護者は答えを言わず、言葉を待ちます。

  2. 10–20分

    AIと使い方の約束を知る

    講師「AIも間違えるよ。名前や住所は入れない。困ったら大人に聞こう。」

    講師が架空の例で実演。入力と出力を一緒に確認し、子どものアカウント作成は求めません。

  3. 20–35分

    自分のアイデアを形にする

    講師「どんな性格？ 何を得意にしたい？ 二つの案を見比べよう。」

    子どもが考え、大人が操作して絵や短い紹介文の案をつくる。既存キャラクターの模写や、子どもの顔写真は使いません。

  4. 35–40分

    画面を離れて休む

    立ち上がる、水分をとる、実物を見直す。端末の操作が苦手な子は、紙と会話で同じ活動に参加できます。

  5. 40–55分

    本当のことと、空想を分ける

    講師「この葉っぱは本当にこの色？ 空を飛べるのは、お話の中だね。」

    AIの出力を実物・図鑑と比較。「合っている」「空想」「まだわからない」に分け、確認した根拠を一つ残します。

  6. 55–70分

    発見カードを完成させる

    絵、名前、自分の発見、AIに手伝ってもらった部分を1枚に。子ども自身が直したところを一つ加えます。

  7. 70–82分

    家族や仲間に伝える

    講師「何を見つけた？ どうしてこの案を選んだの？」

    一人1〜2分で発表。話すのが苦手なら指さしや保護者の代読でも参加できます。作品の上手さを順位づけしません。

  8. 82–90分

    家で試すことをひとつ決める

    「次は何を確かめたい？」を親子で決め、時間・使う場所・大人への相談について家庭の約束を1枚にします。

講師・保護者が入力する例を見る
親子の創作体験を手伝ってください。 題材は、手元で観察した「丸い葉っぱ」です。 見つけた特徴は、緑色・小さな切れ込み・つるつるした表面です。 この特徴を使って、オリジナルのキャラクター案を二つ考えてください。 名前と性格を短く示し、最後に子どもが自分で選べる質問を一つしてください。 植物の種類や育て方は、今の情報だけで断定しないでください。 本当の特徴と、お話の中の空想を分けてください。

指示だけで出力の正確さ・安全性は保証できません。大人が内容を確認してから子どもに見せます。

持ち帰るもの

自分の発見カード1枚、確認できたこと1つ、次の疑問1つ、親子のAIルール1枚。講師は「問いを言えた・確かめた・自分で選んだ」を記録し、改善に使います。

LEARN TOGETHER

親子で守る、5つの約束。

1. 年齢とサービスの条件を守る

小学生の体験は講師・保護者が実際の入力や操作を担当します。ChatGPTは13歳未満の本人利用を想定しておらず、13歳未満への教育利用では大人が操作する必要があります。13〜17歳は保護者の許可が必要です。利用ツールの最新条件は開催前に再確認します。OpenAIの年齢案内

2. 個人がわかる情報を入れない

本名、学校名、住所、連絡先、顔写真などは入力しません。写真を使う場合は物だけを写し、背景や位置情報も大人が確認。作品の保存場所・削除時期を決め、公開や撮影は参加同意と分けて確認します。

3. 答えをそのまま信じない・提出しない

AIの回答は本や実物と照合します。宿題の完成文を自分の作品として提出せず、学校のルールに従い、使った箇所を説明します。健康や安全に関わる判断はAI任せにしません。

4. 道具との会話を、人との関係につなげる

AIキャラクターには気持ちがあると決めつけず、会話をつくる仕組みとして説明します。不安な内容が出たら画面を閉じて大人へ。友達や家族との会話、外遊び、休憩の時間を大切にします。

5. 他の人の作品と気持ちを大切にする

誰かを傷つける画像や文章をつくらない。他人の写真や作品を勝手に入力しない。公開する場合は、素材の権利と本人・保護者の意向を確認します。発表や撮影を断っても参加できる設計にします。

大人が使うプロンプト6例

［　］をその場の観察に置き換えます。子どもの氏名・学校名・顔写真は入れず、大人が入力と回答を確認してください。指示文だけで正しさを保証することはできません。

問いを広げる
題材は［　］。実物で気づいたことは［　］。答えをすぐに教えず、子どもが観察して試せる質問を三つ提案してください。危険な実験や個人情報の入力は求めないでください。
二つの案から選ぶ
子どもが考えた主人公は［　］、性格は［　］です。オリジナルの短いお話の始まりを二案。結末は書かず、子どもが選んで続けるための問いを一つ添えてください。
事実と空想を分ける
この文章［　］の中で、現実について述べた部分と創作として書かれた部分を分けてください。現実の主張は未確認として示し、図鑑や実物で確認する観点を提案してください。出典や確認済みの事実を作らないでください。
自分の言葉を残して直す
子ども本人の文章は［　］です。本人らしい言葉を残し、伝わりにくい箇所だけ二つ提案してください。全文を書き換えず、本人が選べる形にしてください。
発表を手伝う
作品の題材［　］、発見［　］、自分で変えたところ［　］を、1分で話す順番に整理してください。未記入の経験や感情は創作せず、空欄として残してください。
講師が次回を改善する
個人名を含まない運営メモ［　］から、進行・教材・保護者への説明に分けて改善案を整理してください。観測した事実と推測を分け、次回に試す変更は一つだけ推薦してください。
講師の声かけ・つまずきへの対応
  • 手が止まったら：「色・形・手触りのうち、どれなら話せそう？」
  • AIに全部任せたら：「この中の一つだけ、自分ならどこを変える？」
  • 正解を急いだら：「まだわからない箱に置いて、本で調べよう。」
  • 読み書きが負担なら：大人が代筆し、本人は指さし・絵・口頭で選ぶ。
  • 生成に時間がかかったら：確認済み見本で比較を始め、待ち時間を学習時間に変える。
  • 発表したくなければ：個別に講師へ伝えるか、作品を見せるだけでもよい。
1回の講習を継続サービスに育てる記録

子どもについては「問いを出した／実物や本で確認した／自分で選んだ」を観察し、未観察と未達成を混同しません。保護者には「家でも試せそうか」「困った点」を任意で聞きます。

運営は準備時間、実施時間、補助人数、材料費、会場費、ツール利用費、つまずいた工程を集計。少人数1回の結果を教育効果の証明にせず、次回の教材と提供条件の改善に使います。

発見を1枚にまとめる道具。

おすすめの着手順は、①発見カード ②問いのヒント ③事実と空想の分類。まず講師と親子が使える小さな道具として試作し、AIの自動生成は運営上の必要が見えてから加えます。以下10案は未開発の候補です。

01｜発見カードメーカー — 最初に試作

解決すること：紙の内容を1枚に整える手間を減らす。

入力 → 出力：題材・観察3点・自分の工夫・確認した根拠 → 印刷できるカード

最小の試作：入力、プレビュー、印刷の3画面。最初はAIもログインも不要。ページ再読込で内容を消す仕様を明示。

確かめること：空欄・長文・日本語・小画面でも印刷が崩れないこと。子ども自身の記入欄を必ず残す。

02｜問いのヒントカード — 最初に試作

解決すること：質問が思いつかない子の入口をつくる。

入力 → 出力：題材と学年帯 → 「比べる・変えてみる・理由を考える」の質問3枚

最小の試作：講師が確認した質問集をJSONで持ち、条件で絞り込む。生成AIなしで始める。

確かめること：答えを教える文や誘導的な質問に偏らず、観察につながるか。

03｜本当？ 空想？ ボード — 最初に試作

解決すること：事実と創作と未確認を分ける。

入力 → 出力：講師が確認した短文 → 3分類と確認メモ

最小の試作：タップで三つの箱へ分類。ドラッグ操作だけに依存せず、文字ボタンを用意。

確かめること：あいまいな例で断定を求めず「まだわからない」を選べるか。

04｜講師用90分タイマー — 最初に試作

解決すること：進行と休憩を見失わない。

入力 → 出力：各工程の時間 → 次の声かけと残り時間

最小の試作：開始・一時停止・次工程・時間調整。音なしでも状態がわかる。

確かめること：途中停止や延長、画面復帰で時刻がずれないか。時間で子どもを急かさない。

05｜お願い文くらべノート — 体験会の後

解決すること：入力の違いと結果の違いを見比べる。

入力 → 出力：依頼文A/B、講師確認済みの出力A/B → 条件の差と子どもの感想

最小の試作：まず手動貼り付け式。自動採点せず「どちらが目的に合う？」の欄を設ける。

確かめること：同じ題材・条件で比較できるか。生成のゆらぎを性能差と断定しない。

06｜親子の約束シート — 体験会の後

解決すること：家庭での使い方を話し合いやすくする。

入力 → 出力：使う場所・時間・相談相手 → 家庭用の印刷シート

最小の試作：選択肢と自由記入、印刷。氏名・住所不要、初期状態では保存しない。

確かめること：家庭の事情に合わせて空欄を残せるか。禁止事項だけの紙にならないか。

07｜探究の4回ノート — 継続講習から

解決すること：問いがどう変わったかを見返す。

入力 → 出力：各回の問い・観察・変更点 → 4回の振り返り一覧

最小の試作：最初は端末内で開くファイルの書出し・読込み。共有端末の消去手順も設計する。

確かめること：読込み失敗で既存記録を失わないか。クラウド保存は責任者・同意・保存期限確定後。

08｜地域紹介カード工房 — 地域連携から

解決すること：取材内容をわかりやすくまとめる。

入力 → 出力：公開許可を得た情報、根拠URL → 確認待ちの紹介カード

最小の試作：下書きと確認済みを明確に分ける。取材先の確認が終わるまで自動公開しない。

確かめること：営業時間など変わる情報に確認日が付くか。個人宅や子どもの行動範囲を出さない。

09｜講師の教材準備アシスタント — 運営が増えてから

解決すること：学年・時間に合う教材の準備を助ける。

入力 → 出力：個人情報を含まない学年帯・題材・所要時間 → 講習案、必要物、紙の代替案

最小の試作：AI接続は大人用画面に限定。草案を生成して講師が編集・確認する工程を置く。

確かめること：時間の合計、材料の入手性、実物との照合ができるか。生成結果を直接配布しない。

10｜運営ふり返りメモ — 運営が増えてから

解決すること：教材改善と継続可能な価格検討に使う。

入力 → 出力：回ごとの組数・準備時間・材料費・つまずき → 改善事項と1回の運営費メモ

最小の試作：個人名なしの集計から始める。費用は端末・会場・人件費・通信を別項目にする。

確かめること：家族や子どもの順位づけにならず、次回変える点を一つ選べるか。

最初の開発依頼として、そのまま渡せる仕様案
「AI相談キッズ・発見カードメーカー」を試作してください。 対象：講師・保護者が子どもと一緒に操作する画面。 入力：題材、観察したこと三つ、選んだ案、自分で変えた点、確認した方法、次の疑問。 出力：A4の発見カード。本人の考えとAIに手伝ってもらった部分を区別する。 初版：HTML/CSS/JavaScript。ログイン、外部送信、AI接続、サーバー保存なし。 保存方針：画面を閉じると消えることを説明し、ブラウザの印刷から紙・PDFに残せる。 操作：キーボードでも使えるラベル付き入力。390pxで横スクロールを出さない。 確認：空欄、長文、日本語、特殊記号、印刷の改ページ、再読込時の消去。 公開前：講師が模擬データで使い、親子の説明に必要な修正を確認する。

AI接続を加えるときの構成案

1. 大人が入力

題材と目的だけ。送信前に内容を確認。

2. サーバーで制御

認証、入力制限、利用上限、タイムアウト。

3. 講師が出力確認

不適切・不確かな内容は採用せず編集。

4. 子どもが選ぶ

自分の工夫を加えて印刷・持ち帰り。

実装候補は、静的な教材画面をCloudflare Workers Static Assetsで配信し、必要になったAI呼び出しだけWorker側へ分離する構成です。APIキーは公開JavaScriptへ埋め込まず、サーバー側のSecretsで管理します。Static Assets公式資料・Secrets公式資料

開発時に先に決めること：データ・費用・失敗時
  • 入力は個人情報なしの題材に絞る。生成を入れる場合は送信先・保存方針を確認し、自由入力をログへ残さない。
  • 会場ごとの大人用アクセス制御、1回の文字数・生成回数・同時実行の上限を設ける。
  • 初版は文字の案を中心にし、画像は事前生成した見本も用意する。自動再試行は回数を制限する。
  • 1回の費用は「組数×1組の生成回数×実測した単価＋会場・材料・人件費」で記録する。価格表と予算は実装時に確認する。
  • 失敗時は理由を短く示し、紙教材・見本へ進める。回答待ちのまま授業を止めない。
  • 作品のクラウド保存・公開ギャラリーは別段階。保存期限、削除、本人・保護者の意向、公開前確認を設計してから追加する。
4段階で進める開発ロードマップ
  1. 紙で確認：印刷シートで模擬講習。説明につまずく箇所を直す。
  2. 小さく試作：発見カードメーカーを作り、講師が架空データで確認する。
  3. 体験会で検証：3〜4組で、紙より準備や説明が楽になるか観察する。
  4. 必要な機能だけ追加：問いのヒント、講師用AI、継続ノートの順で必要性を判断する。

判断軸はアプリの機能数ではなく、「子どもが考える時間が増えたか」「講師の準備負担が減ったか」です。

FROM HIKONE / ここからの展開

地域の体験を、学びの題材に。

AI相談の強みは、AIを実際の暮らしや現場に結びつけること。植物の観察、地域のお店の紹介、ボルダリング体験の振り返りなど、子どもが本当に経験したことを出発点にします。

たとえば、登る前に予想し、体を動かして試し、終わってから絵や言葉で振り返る。AIは振り返りの表現を手伝い、登り方や安全判断は現場の指導者が担当します。

STEP 01

親子体験会

3〜4組の小規模回で、楽しさ・難しさ・見守り負担を確認。

STEP 02

4回の探究講習

同じ子の問いと作品の変化を見て、教材と進行を改善。

STEP 03

学校・地域との連携

図書館・施設・教室の活動に合わせ、出張講習を検討。

STEP 04

正式メニュー化

対象学年、料金、定員、提供方法を決めて募集を開始。

運営開始前に決めること

講師・補助者の配置、端末と通信環境、使用ツールの規約、保護者の同席、配慮が必要な参加者への対応、同意・データ保存方針、料金とキャンセル条件を確定します。生成が止まった場合は、事前に確認した見本と紙の創作へ切り替えます。

初回は講師1名＋補助1名を想定。作品の完成数だけでなく、子どもが選んだ理由、確認の行動、親の不安の変化、準備・見守りにかかった時間を記録。次回内容と持続可能な料金の判断材料にします。
