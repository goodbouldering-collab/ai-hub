AIコーディング総合講習

Codexを「魔法の自動制作」ではなく、作業を任せて確認する共同作業者として使うための講習資料です。最初にAIコーディングの全体像を押さえ、その流れのままプログラミングを基礎から少しずつ学び、LP・アプリ・資料・公開運用までつなげます。

実装ループ小さく依頼し、差分を見て、ブラウザで確認して直す。
公開運用Vercel、Supabase、SEO、セキュリティ、監視まで理解する。
応用制作LP、講習資料、動画、SNS、業務アプリへ広げる。
00 / Orientation

最初に押さえるAIコーディングの全体像

コードの前に、どのAIが何を担当するかを分けます。ここが分かると、初心者でも「どこで相談し、どこで作業し、どこで確認するか」を迷いにくくなります。

Codexは作業場を持つ

ChatGPTの会話だけではなく、フォルダ、ファイル、コマンド、ブラウザ確認まで同じ流れにできます。だから「できた」という返事より、結果の確認が大事です。

覚える語彙: workspace / diff / review
Slide 00-B

プログラミングはAIへの指示精度を上げる基礎

全部を手書きするためだけに学ぶのではなく、AIが出した変更を理解し、正しく直し、危険な公開を止めるために学びます。

覚える語彙: HTML / CSS / JS / API
Slide 00-C

最初から全自動を狙わない

最初の成功体験は「AIに小さく作らせて、自分が見て選ぶ」ことです。大きな公開作業は、Git差分と独立レビューを挟んでから進めます。

覚える語彙: small task / browser check
01 / Entry

入口: PCと作業場を整える

AIコーディングの最初の山は、難しいアルゴリズムではありません。フォルダ、ターミナル、ブラウザ、Git、秘密情報の置き場所を分けられることです。

基礎へ進む
Slide 01

「どこで何をしているか」を見失わない

初心者がつまずく原因の多くは、AIの能力不足ではなく、作業場所の混乱です。ローカルフォルダ、GitHub、本番URL、管理画面、Notebookや資料の保存先を分けて考えます。

フォルダ作業対象
ターミナル実行結果
ブラウザ見た目
Git変更差分
.env秘密情報
AGENTS.md作業ルール
Slide 01-A

最初に開くもの

  • 制作するプロジェクトのフォルダ
  • VS CodeまたはCodexの作業画面
  • ローカル表示用のブラウザ
  • Git差分または変更一覧

最初は空フォルダでも構いません。重要なのは、AIが触れる範囲を自分で把握することです。

Slide 01-B

最初から触らなくてよいもの

  • モデル設定の細かい比較
  • MCPサーバーの全設定
  • Hooksの自作
  • 大規模な認証や決済

講習の入口では「何を頼むか」「どこを確認するか」「公開してよいか」の判断を先に作ります。

02 / Programming Basics

基礎: AIに任せるためのプログラミング語彙

ここは暗記リストではありません。LPやWebアプリをAIに作らせる時に、何がどの層を担当しているかを説明できるようにします。

実装ループへ
STEP 1

HTML

見出し、段落、リンク、画像、フォーム。ページの意味と構造を作る層。

STEP 2

CSS

余白、色、文字サイズ、レイアウト、スマホ対応。見た目と読みやすさの層。

STEP 3

JavaScript

クリック、入力、保存、表示切替。画面を動かす層。

STEP 4

データ

JSON、YAML、API、DB。情報を持ち、読み書きし、画面へ渡す層。

Slide 02-A

HTMLは「何があるか」

AIに「カードを追加して」と頼む時、実際には見出し、画像、説明文、リンクの構造が必要です。HTMLを少し知ると、AIの出力を読む力が上がります。

Slide 02-B

CSSは「どう見えるか」

余白が詰まる、スマホで崩れる、ボタンの文字がはみ出る。こうした問題はCSSの責任範囲です。AIへの修正指示も具体的になります。

Slide 02-C

JavaScriptは「どう動くか」

タブ、検索、保存、API呼び出し、フォーム送信。画面が反応するところはJavaScriptです。エラーの場所もここに出やすくなります。

Slide 02-D

React / Next.jsは部品化

同じ見た目を繰り返す、ページごとに状態を持つ、サーバー側でデータを読む。実務ではHTML/CSS/JSを部品として組み合わせます。

Slide 02-E

APIとDBは「情報の出入口」

問い合わせ、記事、ユーザー、商品、在庫。画面に出る情報は、APIやデータベースから来ます。公開後の不具合はこの層にも起きます。

Slide 02-F

Markdown / YAMLは教材と設定の入口

講習資料、カード一覧、設定ファイルはコードより読みやすい形式で持てます。AIに編集させる時も、構造が明確なファイルは扱いやすいです。

03 / Build Loop

実装: AIと一緒に作る作業ループ

プログラミングを学ぶ目的は、AIの出力を信じ込むことではありません。小さく頼み、画面で確認し、差分を読んで、次の指示を出すことです。

公開・運用へ
Slide 03

1回の依頼を「作業単位」に切る

よい依頼は、AIに全部を丸投げする文章ではなく、作業対象、完了条件、確認方法、触ってはいけない範囲が分かる文章です。

このフォルダで、講習LPの「基礎」セクションだけを見直してください。 AGENTS.mdのルールに従ってください。 変更前に対象ファイルを確認し、完了後にブラウザ表示とリンクを確認してください。 本文の意味は変えず、初心者が順番に学べる構成へ整理してください。
Slide 03-A

依頼に入れる4点

  • 何を作るか
  • 誰が読むか
  • どこを触るか
  • 何で確認するか
Slide 03-B

確認は3種類

  • 表示確認: ブラウザで崩れを見る
  • 差分確認: 変更されたファイルを見る
  • 独立レビュー: 壊れそうな点を別視点で出す
「AIが作った」ではなく「自分が採用した」に変える

AIコーディングを応用する人に必要なのは、全コードを暗記する力ではなく、成果物を判断する力です。だから基礎語彙、確認方法、レビュー依頼を講習の中心に置きます。

実務運用を見る
04 / Publish and Ops

公開: Git・テスト・デプロイ・運用をつなげる

AIが画面を作れるようになった後、実務で必要になるのは公開して壊さない力です。ここからはWeb制作が業務システムに近づきます。

AI応用へ
Slide 04-A

Gitは変更の履歴

失敗しても戻れる、何を変えたか説明できる、別案を比較できる。AIに作らせるほどGitの重要度は上がります。

  • status
  • diff
  • commit
  • branch / worktree
Slide 04-B

テストとビルドは最低限の関門

見た目が良くても、構文エラー、リンク切れ、APIエラーがあれば公開できません。AIに「何を確認したか」を報告させます。

  • syntax check
  • build
  • 主要リンク
  • フォーム送信
Slide 04-C

デプロイは本番へ届ける作業

Vercel、GitHub Pages、サーバー、ドメイン。どこが本番URLかを取り違えないことが、公開作業の第一条件です。

  • production URL
  • preview URL
  • domain
  • environment variables
Slide 04-D

DBと認証は慎重に扱う

Supabase、Shopify、Googleログイン、管理画面。書き込みや秘密情報を扱う箇所は、確認モーダルや権限設計をセットにします。

Slide 04-E

SEO / LLMOは読まれる設計

タイトル、見出し、構造化データ、OGP、本文の説明力。検索エンジンにもAI検索にも、ページの意図が伝わるように作ります。

Slide 04-F

監視は公開後の授業

アクセス、エラー、表示速度、問い合わせ、検索流入。公開後に何が起きたかを見ることで、次の改善依頼が具体的になります。

05 / AI Production

応用: コードから教材・LP・業務制作へ広げる

AIコーディングの応用先は、Webアプリだけではありません。LP、講習資料、動画、SNS、CMS、業務管理画面を同じプロジェクトの成果物として扱います。

実務運用へ
Slide 05-A

LPは「作って見せる」練習に向く

見出し、導線、カード、FAQ、問い合わせ。視覚確認がしやすく、HTML/CSS/JSの基礎をまとめて学べます。このページ自体もLP型の講習資料です。

Slide 05-B

講習資料はコードで管理できる

Markdown、HTML、スライド、動画、PDFを同じリポジトリに置くと、更新履歴が残り、AIに再構成や要約を任せやすくなります。

Slide 05-C

CMSはAI編集の受け皿になる

WordPress、独自/studio、Payloadの違いは、誰がどこで編集し、どのデータを画面へ出すかです。AIで下書きし、人が確認して公開します。

Slide 05-D

Creative Productionで素材まで作る

画像、広告案、SNS投稿、動画台本、プレゼン資料。コードの外側も、要件整理と確認の流れは同じです。

1
コンテンツを構造化見出し、要約、カード、FAQ、CTAに分ける。
2
AIに初稿を任せる文章、配置、画像案、台本を作らせる。
3
画面で直すスマホ、文字量、余白、リンクを確認する。
4
公開前に止める秘密情報、誤情報、権利、表示崩れを確認する。
06 / Codex Operations

実務運用: Codexを安全に拡張する

基礎と制作ループを理解したら、プラグイン、Skills、Hooks、MCP、Apps、worktree、独立レビューを使って、実務の作業範囲を広げます。

総合演習へ
Slide 06-A

ロール別プラグインは仕事別の道具箱

Data analytics、Creative production、Sales、Product design、Public equity investing、Investment bankingのように、仕事の進め方と接続先をまとめて渡します。

Slide 06-B

Skills / Hooks / Scripts

Skillsは手順書、Hooksは自動チェック係、Scriptsはよく使う処理の実行ボタンです。最初は存在を理解し、必要になった時に増やします。

Slide 06-C

MCP / Apps / Connectors

GitHub、Figma、Gmail、Canva、Supabaseなどに接続する入口です。ログイン済みサービスや外部データを扱う時ほど、権限と公開範囲に注意します。

Slide 06-D

Browser / Chrome / Computer Use

ローカル表示はBrowser、ログイン済み画面はChrome、ブラウザ外のWindows操作はComputer Use。確認対象に合わせて道具を選びます。

Slide 06-E

worktreeで別案を試す

大きな変更、デザイン案、危険な実験は本線から分けます。AIに複数案を作らせる時も、差分を分けると採用判断が楽になります。

Slide 06-F

独立レビューは公開前のブレーキ

レビュー依頼では、褒めるよりもバグ、表示崩れ、説明不足、秘密情報、公開前に止めるべき点を重大度順に出してもらいます。

07 / Exercises

総合演習: だんだん作れるようになる4本立て

最終的には、AIに任せる範囲を少しずつ広げながら、公開できる成果物を作ります。各演習は、講習中に投影しやすい1枚スライドとして扱えます。

先頭へ戻る
Exercise 1

自己紹介LPを作る

HTML/CSS、画像、リンク、スマホ表示を学びます。Codexにはセクション追加やデザイン調整を小さく依頼します。

  • 完成物: 1ページLP
  • 確認: ブラウザとリンク
  • 学ぶ語彙: hero / card / CTA
Exercise 2

講習資料を再構成する

Markdown、見出し、要約、スライド調UIを学びます。内容の流れをAIに整理させ、人が読みやすさを判断します。

  • 完成物: 講習LP
  • 確認: 文字量と見出し
  • 学ぶ語彙: Markdown / section / summary
Exercise 3

問い合わせフォームを作る

JavaScript、API、入力検証、送信後の表示を学びます。秘密情報や書き込み処理は慎重に確認します。

  • 完成物: 動くフォーム
  • 確認: 入力と送信
  • 学ぶ語彙: form / API / validation
Exercise 4

公開してレビューする

Git、ビルド、Vercel、SEO、独立レビューを学びます。本番URLを確認し、公開前に止めるべき点を洗い出します。

  • 完成物: 公開ページ
  • 確認: 本番URLと差分
  • 学ぶ語彙: deploy / env / review
この講習のゴール

受講後は、AIに「何を作るか」を説明し、AIが作ったものをブラウザと差分で確認し、必要な基礎用語を使って修正依頼できる状態を目指します。

AIに質問する

AIコーディングは、作れる人だけの技術ではなく、作業を設計して確認できる人の技術です。

この資料は、Codex導入講習、プログラミング基礎、制作演習、公開前レビューを1本にまとめた総合講習LPとして使えます。投影時は各スライドを1章ずつ送り、通常閲覧時はLPとして上から順に読めます。
